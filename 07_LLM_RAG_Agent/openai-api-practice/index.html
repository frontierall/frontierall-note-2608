4. 첫 번째 API 호출

4-1. 역할 부여 + 길이·추론 조절

response = client.responses.create(
    model="gpt-5.6-luna",
    instructions="너는 친절한 여행 전문가야. 한국어로 답해줘.",
    input="서울 2박 3일 여행 코스 추천해줘",
    reasoning={"effort": "low"},
    max_output_tokens=800
)

print(response.output_text)

Reasoning Effort 고르기

effort특징추천 용도
none⚡ 추론 없이 즉답, 가장 빠르고 저렴단순 분류, 형식 변환, 짧은 답변
low🌱 가볍게 생각일반 대화, 간단한 요약
medium⚖ 속도와 추론의 균형대부분의 일반 작업
high🔍 더 깊게 생각, 느리고 비용 증가복잡한 분석, 코딩, 문제 해결
xhigh🧠 가능한 범위에서 가장 깊게 추론난이도 높은 문제, 복잡한 설계
🎛 예전 temperature 실습을 대체하는 부분입니다. "0.2 vs 0.9" 비교 대신 effort: none vs high를 비교하면 응답 속도·비용·품질 차이가 훨씬 뚜렷하게 보입니다.

5. 대화 이어가기

예전에는 messages 리스트에 assistant 응답을 직접 append 했습니다. 이제는 직전 응답 ID만 넘기면 서버가 맥락을 이어받습니다. 이 방식은 도전 6-4에서 그대로 쓰이니 눈여겨보세요.

from openai import OpenAI

# 첫 번째 질문
response = client.responses.create(
    model="gpt-5.6-luna",
    instructions="너는 미래 전문가야.",
    input="사람들은 어떻게 미래를 대비해야 할까?"
)
print("AI:", response.output_text)

# 대화 반복
for _ in range(3):
    user_input = input("\n추가 질문을 입력하세요 (종료: q): ")
    if user_input.strip().lower() == "q":
        break

    response = client.responses.create(
        model="gpt-5.6-luna",
        input=user_input,
        previous_response_id=response.id    # ← 여기가 핵심
    )
    print("AI:", response.output_text)

기본 6-1

모델 바꾸기 · 지침 넣기

4장 코드에서 model을 다른 모델로 바꾸고, instructions를 추가해 답변의 말투가 어떻게 달라지는지 확인합니다.

할 일

  • model을 gpt-5.6-terra 또는 gpt-5.6-sol로 바꿔 실행해 보세요.
  • instructions를 추가해 AI에게 역할을 주세요. (예: 진로 상담 선생님, 냉정한 분석가)
  • 같은 질문인데 답변이 어떻게 달라졌는지 한 줄로 적어 보세요.

시작 코드

response = client.responses.create(
    model="gpt-5.6-luna",          # ← 여기를 바꿔 보세요
    # instructions="..."          ← 이 줄을 추가해 보세요
    input="미래에 꼭 필요한 직업은 어떤 것이 될까요?"
)

print(response.output_text)
💡 힌트
  • instructions는 model, input과 나란히 놓는 인자입니다. 줄 끝의 쉼표를 빠뜨리지 마세요.
  • 역할은 구체적일수록 차이가 잘 보입니다. "친절하게"보다 "중학생도 알아듣게, 마지막에 한 줄 요약"처럼요.
  • 모델 이름은 오타가 나면 바로 오류가 납니다. 위 모델 선택 상자를 바꾸면 이 페이지의 코드가 통째로 바뀌니 그대로 복사해 쓰세요.
기본 6-2

질문을 입력받아 답변하기

질문을 코드에 고정하지 말고 input()으로 사용자에게 받아서 그대로 AI에게 넘깁니다.

할 일

  • input()으로 질문을 받으세요.
  • 받은 값을 client.responses.create()의 input에 넣으세요.
  • 아무것도 입력하지 않고 엔터를 치면 어떻게 되는지도 확인해 보세요.
⚠ 파이썬 함수 input() 과 API 인자 input= 은 이름만 같고 서로 다른 것입니다. 변수 이름을 input 으로 지으면 함수가 덮어써져 다음 호출에서 오류가 납니다. question 처럼 다른 이름을 쓰세요.
💡 힌트
  • question = input("궁금한 것을 입력하세요: ") 로 받아 두고, 그 변수를 input=question 에 넘깁니다.
  • 빈 입력을 걸러내려면 question.strip() 이 비었는지 확인하세요. 공백만 친 경우까지 잡힙니다.
  • 걸러내지 않으면 빈 질문도 그대로 API로 나가서 요금만 나가고 쓸모없는 답이 돌아옵니다.
기본 6-3

여러 개의 질문을 한 번에 돌리기

질문 3개를 리스트에 담고 반복문으로 차례차례 물어봅니다. 반복문 하나로 API 호출이 자동화되는 것을 경험합니다.

주어진 질문 목록

questions = [
    "미래에 꼭 필요한 직업은?",
    "10년 뒤 사라질 직업은?",
    "AI가 대체하기 어려운 직업은?",
]

할 일

  • for 문으로 질문을 하나씩 꺼내 API에 보내세요.
  • 어떤 질문에 대한 답인지 알아볼 수 있게 질문도 같이 출력하세요.
  • 3개를 도는 데 시간이 얼마나 걸리는지 체감해 보세요.
💡 힌트
  • for q in questions: 로 돌리고, 번호까지 붙이고 싶으면 enumerate(questions, 1) 을 쓰세요.
  • 결과가 뒤섞여 보이면 print("=" * 50) 같은 구분선을 넣어 보세요.
  • 질문마다 API를 한 번씩 부르므로 요금도 3배입니다. instructions에 "5줄 이내로"를 넣어 답변을 짧게 만들면 부담이 줄어듭니다.
도전 6-4

되묻는 AI 만들기

Claude에게 뭔가를 시키면 바로 답하지 않고 "어떤 용도인가요?", "대상이 누구인가요?"처럼 먼저 되묻는 경우가 있습니다. 그 뒤 내 대답을 반영해 훨씬 정확한 답을 줍니다. 이 흐름을 직접 만들어 봅니다.

만들 흐름

1단계  사용자가 질문을 입력한다
         ↓
2단계  AI가 답 대신, 확인 질문 2~3개를 던진다
         ↓
3단계  사용자가 그 질문들에 답한다
         ↓
4단계  AI가 1~3단계를 모두 반영해 최종 답변을 한다

할 일

  • 2단계에서 AI가 답을 하지 않고 질문만 하도록 만드세요.
  • 3단계의 사용자 답변을 받아 4단계로 넘기세요. 이때 AI는 1단계 질문을 기억하고 있어야 합니다.
  • 같은 질문을 되묻기 없이 한 번에 답하게 했을 때와 답변이 얼마나 달라지는지 비교해 보세요.
💡 힌트
  • 핵심은 instructions입니다. "바로 답하지 말고, 답변에 꼭 필요한 확인 질문을 2~3개만 번호를 붙여 물어봐"처럼 행동을 금지하고 대신 할 일을 지정하세요.
  • 맥락을 잇는 것은 5장의 previous_response_id입니다. 두 번째 호출에 previous_response_id=first.id 를 넘기면 AI가 원래 질문과 자기가 던진 확인 질문을 모두 기억합니다. 이걸 빼면 AI는 사용자의 답만 덩그러니 받고 무슨 얘기인지 모릅니다.
  • 두 번째 호출의 input에는 사용자의 답변을 넣고, instructions는 "이제 위 답변을 반영해 최종 답을 해줘"로 바꿔 주면 깔끔합니다.
  • 확인 질문이 여러 개라 입력받기가 번거로우면, 우선 한 번에 한 줄로 받아 보세요. 여유가 되면 for 문으로 질문을 하나씩 나눠 받는 형태로 발전시킬 수 있습니다.

수업용 링크 만들기 (URL 파라미터)

주소 뒤에 ? 를 붙여 조합합니다. 두 개 이상은 & 로 잇습니다. 화면에서 버튼을 누르면 주소도 함께 바뀌므로, 원하는 화면을 만든 뒤 "현재 화면 링크 복사"를 눌러도 됩니다.

파라미터값하는 일
step6-1 ~ 6-5그 실습으로 바로 이동하고 파란 테두리로 강조합니다.
onlypractice교안을 감추고 실습 과제만 보여 줍니다. 과제 배포용.
model모델 이름페이지의 모든 코드에서 모델명을 그 값으로 바꿔 줍니다.
hintopen 또는 6-4open은 힌트 전체 공개, 번호를 주면 그 문제 힌트만 엽니다.

바로 써먹는 링크

  • ?only=practice — 학생에게 과제만 배포
  • ?step=6-3 — "지금 6-3 하세요"
  • ?only=practice&model=gpt-5.6-terra — 오늘은 terra 모델로 과제
  • ?step=6-4&hint=6-4 — 도전 과제를 힌트까지 펼쳐서 설명
  • ?hint=open — 막힌 사람이 많을 때 힌트 전체 공개
정답 코드는 아직 넣지 않았습니다. 수업에서 충분히 고민한 뒤 공개하려고 비워 둔 자리입니다.
