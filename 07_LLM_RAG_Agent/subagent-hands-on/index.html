01오늘 만들 것 — 한 문장 소개

코드 한 줄 없이, 텍스트 파일 하나로 나만의 "조사 담당"을 만듭니다.

이 문서를 다 따라 하면, 문서 하나를 던져주면 웹을 검색해서 "여기 오래된 정보가 있어요"라고 근거와 함께 알려주는 나만의 AI 하나가 생깁니다. 이름은 doc-researcher라고 짓겠습니다.

미리 말씀드리면, 이 하나만으로는 아직 "완성된 도구"는 아닙니다. 스스로 판단만 하고 파일을 고치지는 않습니다(일부러 그렇게 만듭니다 — 이유는 아래에서). 이 doc-researcher를 검증하는 두 번째 에이전트는 다음 교안 doc-fact-checker 만들기에서, 문서를 실제로 고치는 기능까지는 그다음 문서 최신화·팩트체크 에이전트 만들기에서 이어집니다. 오늘은 그 첫 조각 하나만, 제대로 이해하면서 만드는 게 목표입니다.

02그냥 채팅으로 물어보면 안 되나요?

됩니다. 그런데 그때그때 다르게 됩니다. 그게 문제입니다.

지금 Claude Code 채팅창에 그냥 이렇게 쳐도 비슷한 답을 받을 수 있습니다.

"이 문서 읽고 웹 검색해서 오래된 내용 있으면 알려줘."

그런데 이렇게 매번 물어보면 몇 가지가 자꾸 어긋납니다.

그냥 채팅에 매번 물어보기에이전트로 만들어두기
규칙매번 설명을 다시 써야 함. 까먹고 안 쓰면 결과가 그때그때 달라짐파일 하나에 규칙을 한 번 적어두면 항상 똑같이 지켜짐
안전지금 이 대화창은 파일을 고칠 힘도 그대로 가지고 있음"이 일만 하는 애"는 아예 파일 수정 도구를 안 쥐어줄 수 있음
재사용다른 프로젝트에서는 처음부터 다시 설명파일 하나를 복사하거나 연결만 하면 다른 프로젝트에서도 똑같이 동작
한 줄로 요약하면

에이전트는 "이 일은 항상 이 규칙으로, 이 도구만 써서 하라"고 미리 적어둔 메모입니다. 특별한 게 아니라, 매번 다시 설명하기 귀찮은 일을 텍스트 파일 하나로 저장해두는 것뿐입니다.

03언제 에이전트로 만드는 게 좋은가

모든 걸 에이전트로 만들 필요는 없습니다. 아래 셋 중 하나라도 해당하면 만들 가치가 있습니다.

  • 같은 요청을 반복하고 있을 때"이 문서 최신 정보로 확인해줘"를 이번 주에만 세 번째 치고 있다면, 그건 메모해둘 가치가 있는 규칙입니다.
  • "이 작업은 절대 파일을 고치면 안 된다"처럼 못박고 싶을 때사람이 매번 조심하는 것보다, 애초에 그 힘을 안 주는 게 확실합니다.
  • 다른 프로젝트에서도 똑같이 쓰고 싶을 때파일 하나로 저장해두면 복사·연결만으로 재사용됩니다.
반대로 필요 없을 때

딱 한 번, 지금 이 대화에서만 필요한 일이라면 그냥 채팅으로 물어보는 게 더 빠릅니다. 메모(에이전트)를 만드는 것도 품이 드는 일이니, "또 쓸 것 같다" 싶을 때만 만드세요.

04준비물

특별한 프로그램을 새로 설치할 필요는 없습니다.

  • Claude Code가 실행되는 프로젝트 폴더 (지금 보고 계신 이 강의 자료 저장소도 좋습니다)
  • 텍스트 파일을 만들고 저장할 수 있으면 충분합니다 — Claude Code 안에서 직접 만들어도 됩니다

05직접 만들기 — 8단계

하나씩 그대로 따라 하면 됩니다. 중간에 이해가 안 가는 단어가 나오면 09장 용어 정리를 먼저 펴보세요.

1

폴더 위치 정하기

지금 열려 있는 프로젝트 폴더(맨 위 루트) 바로 아래에 .claude라는 폴더가 있는지 확인합니다. 없으면 새로 만듭니다. 그 안에 다시 agents라는 폴더를 만듭니다.

결과적으로 이런 모양이 됩니다: <프로젝트 폴더>/.claude/agents/

지금 단계에서는 이 프로젝트 안에만 있는 "이 프로젝트 전용" 위치에 만듭니다. 여러 프로젝트에서 같이 쓰는 방법은 다음 교안에서 다룹니다 — 처음부터 그것까지 신경 쓰면 헷갈립니다.

2

파일 만들기

방금 만든 agents 폴더 안에 doc-researcher.md라는 이름으로 새 파일을 만듭니다. .md는 "마크다운"이라는, 그냥 글자로만 된 문서 형식입니다. 특별한 프로그램 없이 메모장으로도 열립니다.

3

맨 위에 "이 파일에 대한 설명" 적기 (frontmatter)

파일 맨 위에 ---로 시작하고 ---로 끝나는 부분을 적습니다. 이걸 frontmatter라고 부르는데, "이 에이전트의 이름표"라고 생각하면 됩니다.

---
name: doc-researcher
description: 문서를 읽고 웹 검색으로 최신 정보와 대조해서, 오래되거나
             틀린 것 같은 부분을 근거와 함께 목록으로 알려주는 조사 담당.
             "이 문서 최신 정보로 확인해줘" 같은 요청에 사용한다.
tools: Read, WebSearch, WebFetch
---

세 줄이 전부입니다. 각각 무슨 뜻인지 볼게요.

  • name — 이 에이전트를 부를 때 쓰는 이름입니다. 파일 이름과 맞춰두면 헷갈리지 않습니다.
  • description — "이건 언제 쓰는 애인가"를 적습니다. Claude가 이 설명을 보고 "아, 지금 이 일엔 doc-researcher를 부르면 되겠다"고 판단하기 때문에, 대충 쓰면 필요할 때 안 불려오거나 엉뚱할 때 불려옵니다.
  • tools — 이 에이전트가 쓸 수 있는 도구 목록입니다. 여기가 가장 중요합니다. Read(파일 읽기), WebSearch·WebFetch(웹 검색/가져오기)만 줬습니다. 파일을 고치는 도구(Write, Edit)는 일부러 넣지 않았습니다. 목록에 없으면 애초에 쓸 수가 없어서, "실수로 파일을 고칠까 봐 조심"할 필요 자체가 없어집니다.
4

본문에 규칙 적기

frontmatter 아래(두 번째 --- 다음 줄부터)에 이 에이전트가 지킬 규칙을 사람 말로 적습니다. 아래 정도면 충분합니다.

# Doc Researcher

당신은 문서를 읽고, 웹 검색으로 최신 정보와 비교하는 조사 담당입니다.

## 하는 일
1. 받은 문서를 먼저 전체 읽습니다.
2. 시간이 지나면 바뀔 수 있는 내용(버전, 가격, 날짜, 정책, 링크 등)을
   골라서 웹으로 검색해 지금도 맞는지 확인합니다.
3. 발견한 것마다 이렇게 정리해서 보고합니다:
   - 위치: 문서의 어느 부분인지
   - 현재 내용 / 제안 변경
   - 근거: 확인한 웹페이지 주소
   - 확신도: 확인됨 / 추정 / 불확실

## 지켜야 할 것
- 파일을 고치지 않습니다. 목록으로 보고만 합니다.
- "예전에 배운 걸로 아는" 내용도 반드시 실제 검색으로 다시 확인합니다.
- 근거(출처)가 없는 내용은 목록에 넣지 않습니다.
5

저장하기

파일을 저장합니다. 이게 전부입니다 — 설치할 것도, 실행 버튼을 누를 것도 없습니다.

6

Claude Code를 새로 열기(또는 새 세션 시작)

지금 세션이 켜져 있었다면 이 프로젝트를 다시 열거나 새 세션을 시작하세요. 에이전트 목록은 세션이 시작할 때 한 번 읽어오기 때문에, 방금 만든 파일은 다음번에 열 때부터 인식됩니다.

7

불러서 써보기

채팅창에 이렇게 요청해보세요.

"doc-researcher 에이전트로 <점검하고 싶은 문서 경로>를 확인해줘."

이름을 직접 말하지 않아도, description에 맞는 자연스러운 요청("이 문서 최신 정보로 확인해줘")이면 자동으로 이 에이전트가 불려올 수 있습니다.

8

결과 기다리기

doc-researcher가 문서를 읽고 검색해서 목록을 정리해 돌아옵니다. 이 결과를 어떻게 읽어야 하는지는 바로 다음 장에서 다룹니다.

06써보고 결과 읽는 법

돌아온 목록을 어떻게 대해야 하는지가 이 실습의 진짜 핵심입니다.

이렇게 돌아옵니다

예시 결과 (형태만 예시입니다)

위치: "설치 방법" 문단, "버전 2.1을 내려받으세요"
현재 내용: 버전 2.1
제안 변경: 버전 3.0 (2026년 상반기 출시)
근거: https://example.com/release-notes (공식 릴리스 노트)
확신도: 확인됨

여기서 멈추세요. "확인됨"이라고 나왔어도, 이 결과를 그대로 문서에 바로 반영하면 안 됩니다. doc-researcher 혼자 낸 결론이고, 아직 아무도 다시 확인하지 않았습니다.

지금 단계에서는 이 목록을 사람이 눈으로 직접 원본 링크를 열어보고 맞는지 확인한 뒤, 맞다고 판단되면 사람이 직접 문서를 고치는 것까지가 정상적인 사용법입니다. "검색 → 검증 → 반영"을 전부 자동으로 이어붙이는 건 다음 교안의 몫입니다.

07여기서 멈추는 이유 — 다음엔 뭐가 필요한가

doc-researcher 하나만으로는 두 가지가 부족합니다. 일부러 그렇게 만들었습니다.

  • 재검증이 없습니다. doc-researcher가 "확인됨"이라고 적었어도, 검색 결과 하나를 잘못 읽었을 수 있습니다. 다른 눈으로 한 번 더 봐야 합니다.
  • 자동으로 반영되지 않습니다. 지금은 사람이 매번 목록을 읽고 직접 문서를 고쳐야 합니다. 문서가 많아지면 이게 번거로워집니다.

첫 번째를 채우는 게 바로 다음 교안 doc-fact-checker 만들기입니다. 오늘 만든 doc-researcher는 그대로 재사용하고, 독립적으로 다시 확인하는 검증 담당을 하나 더 만들어 손으로 이어서 써봅니다. 두 번째(자동 반영)까지 채우는 건 그다음 문서 최신화·팩트체크 에이전트 만들기에서, 작성 담당과 오케스트레이션 스킬을 더해 마무리합니다.

08막혔을 때 체크리스트

  • 에이전트가 안 불려온다새 세션으로 다시 열었는지 확인하세요. 파일 경로가 <프로젝트>/.claude/agents/doc-researcher.md가 맞는지도 확인하세요.
  • frontmatter 형식이 이상하다는 느낌이 든다---로 시작하고 ---로 끝나는지, 그 사이 들여쓰기가 이상하게 꼬이지 않았는지 확인하세요.
  • 검색을 안 하고 그냥 아는 척 답한다description과 본문에 "반드시 웹 검색으로 확인하라"는 문장이 있는지 확인하세요. 애매하게 적으면 건너뛸 수 있습니다.

09용어 정리 & 다음 단계

용어뜻
서브 에이전트메인 대화와 별도로 특정 일을 맡는 AI. .md 파일 하나로 정의한다.
.md 파일 (마크다운)글자로만 이루어진 간단한 문서 형식. 메모장으로도 열린다.
frontmatter파일 맨 위, --- 사이에 적는 "이 파일에 대한 설명" 부분.
tools이 에이전트가 쓸 수 있는 기능 목록. 여기 없는 기능은 아예 쓸 수 없다.
읽기 전용파일을 고치는 도구(Write/Edit)를 주지 않아, 조사만 하고 수정은 못 하게 만든 상태.
오늘 한 것을 한 문장으로

텍스트 파일 하나(frontmatter + 규칙)로 "읽기 전용 조사 담당" AI를 만들고, 실제로 불러서 써봤습니다. 다음 교안에서 이 파일을 그대로 재사용해 검증 담당을 더합니다.
