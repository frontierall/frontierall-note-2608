Vercel이 무엇인가

Vercel(버셀)은 Netlify와 같은 부류의 서비스입니다. GitHub에 코드를 올리면 알아서 빌드하고, 인터넷 주소를 붙여서 띄워 주는 배포·호스팅 플랫폼이죠. 다만 한 가지 결정적인 차이가 있습니다. Next.js를 만든 회사가 직접 운영하는 서비스라서, Next.js 프로젝트를 올리면 아무 설정 없이 가장 잘 맞게 돌아갑니다. 이 과정에서 쓰는 v0도 같은 회사 제품이라, "v0로 화면을 뽑고 → Next.js 코드로 받아 → Vercel에 올리는" 흐름이 한 회사 안에서 이어집니다.

  • Vercel이 정확히 무엇이고, Next.js·v0와 어떤 관계인지
  • Production · Preview · Development 세 가지 배포 환경
  • 가장 빠른 배포 두 가지 — 대시보드 Import, Vercel CLI
  • 알아 두면 좋은 기능(미리보기 댓글, 환경 변수, 서버리스 함수, 롤백)
  • Netlify와 무엇이 다른지, 언제 무엇을 고르는지
  • 수업에서 실제로 자주 막히는 지점과 해결법

1. 한 줄로 말하면

Vercel은 프론트엔드 프로젝트를 GitHub와 연결해 자동으로 빌드·배포하고, 전 세계에 빠르게 서빙해 주는 플랫폼입니다. 2015년 ZEIT라는 이름으로 시작해 2020년 Vercel로 이름을 바꿨고, 그 사이 2016년에 Next.js를 만들어 공개했습니다. 즉 "프레임워크를 만든 회사가 그 프레임워크를 가장 잘 돌리는 서버까지 같이 판다"는 구조입니다.

1-1. 한 회사, 세 가지 제품

이 과정에서 만나는 Vercel 계열 제품은 세 가지입니다. 이름이 달라서 별개처럼 보이지만 전부 같은 회사이고, 서로 이어지도록 설계돼 있습니다.

제품역할이 과정에서
v0말로 설명하면 화면(UI)을 코드로 만들어 주는 AI 도구PART 04 노코드 프로토타이핑
Next.jsReact 위에 페이지 이동·서버 처리·최적화를 얹은 프레임워크v0가 뽑아 주는 코드의 기본 형태
Vercel그 코드를 올려서 실제 주소로 띄워 주는 배포 플랫폼이 교안

화면 생성 → 코드 → 배포가 한 회사 안에서 이어집니다

2. Vercel의 핵심 — 배포 환경이 세 가지

Vercel을 이해하는 열쇠는 "어느 브랜치에 push했느냐에 따라 배포가 다른 곳으로 간다"는 점입니다. Netlify에도 비슷한 기능이 있지만, Vercel은 이 구분이 화면 곳곳에 훨씬 전면에 나옵니다.

환경언제 만들어지나주소
Productionmain 브랜치에 push할 때내프로젝트.vercel.app (또는 내 도메인)
Preview다른 브랜치에 push하거나 PR을 열 때브랜치 이름이 들어간 별도 주소가 매번 생김
Development내 컴퓨터에서 vercel dev 실행localhost:3000

어디에 push했느냐가 곧 어느 주소로 가느냐를 정합니다

실제 사용자는 Production 주소만 봅니다. 팀원이나 강사에게 "이 기능 이렇게 만들었는데 어때요?"라고 보여 줄 때는 Preview 주소를 보냅니다. Production을 건드리지 않고도 결과물을 공유할 수 있으니, 해커톤에서 여러 명이 동시에 작업할 때 특히 빛을 발합니다.

3. 실습 A — 대시보드에서 GitHub 저장소 가져오기

가장 표준적인 방법입니다. 처음 한 번만 하면 이후는 push만으로 자동 배포됩니다.

  1. vercel.com에 GitHub 계정으로 가입합니다. (이메일 가입보다 GitHub 로그인이 이후 연동이 훨씬 간단합니다.)
  2. 대시보드에서 Add New… → Project를 누릅니다.
  3. Import Git Repository 목록에서 배포할 저장소 옆의 Import를 누릅니다. 목록에 안 보이면 "Adjust GitHub App Permissions"로 저장소 접근 권한을 추가합니다.
  4. 설정 화면에서 Framework Preset이 자동으로 잡혔는지 확인합니다. (Next.js, Vite, Create React App, Astro, SvelteKit 등은 자동 인식됩니다.)
  5. Deploy를 누르면 빌드 로그가 흐르고, 1~2분 뒤 축하 화면과 함께 주소가 나옵니다.

3-1. 설정 화면에서 볼 것은 세 칸

항목의미보통은
Framework Preset어떤 도구로 만든 프로젝트인지자동 인식 그대로
Root Directory저장소 안에서 프로젝트가 있는 폴더루트면 비워 둠. frontend/ 같은 하위 폴더에 있으면 지정
Environment Variables.env에 있던 값들Supabase 키 등이 있으면 여기서 미리 등록

실전 트러블슈팅 — 프로젝트 이름 규칙: Vercel 프로젝트 이름은 소문자·숫자·하이픈만 허용되고 ---처럼 하이픈이 세 번 연속되면 안 됩니다. 저장소 이름에 대문자가 섞여 있으면 Vercel이 자동으로 소문자로 바꿔 주지만, CLI로 만들 때는 실패할 수 있습니다. 자세한 대응은 Claude Code에서 새 프로젝트 만들기 교안의 2장을 참고하세요.

4. 실습 B — 터미널에서 Vercel CLI로 배포

대시보드를 거치지 않고 터미널에서 바로 올리는 방법입니다. Claude Code 같은 AI 코딩 도구와 함께 쓸 때 이 방식이 더 자연스럽습니다.

# 1) CLI 설치 (한 번만)
npm i -g vercel

# 2) 로그인 (브라우저가 열림)
vercel login

# 3) 프로젝트 폴더에서 실행 → Preview 배포
vercel

# 4) 실제 서비스 주소(Production)로 배포
vercel --prod

처음 vercel을 실행하면 "어느 계정에 올릴지", "프로젝트 이름은 무엇으로 할지" 같은 질문을 몇 개 하고, 답하고 나면 .vercel/ 폴더가 생기면서 그 폴더가 어떤 Vercel 프로젝트와 연결됐는지 기억합니다. 이후로는 질문 없이 바로 배포됩니다.

--prod 하나 차이로 도착지가 달라집니다

주의: vercel만 치면 Preview로 올라가고, --prod를 붙여야 실제 주소에 반영됩니다. "배포했는데 사이트가 안 바뀌어요"의 절반은 이 차이입니다. 그리고 .vercel/ 폴더는 .gitignore에 넣어 커밋하지 않습니다.

5. 알아 두면 좋은 기능

5-1. Preview 배포 + 화면 위 댓글

PR을 열면 Vercel 봇이 PR에 Preview 주소를 댓글로 달아 줍니다. 그 주소로 들어가면 화면 아래 Vercel Toolbar가 뜨는데, 여기서 화면의 특정 위치를 클릭해 댓글을 남길 수 있습니다. "이 버튼 색 바꿔 주세요"를 말로 설명하지 않고 버튼을 찍어서 적으면 됩니다.

5-2. 환경 변수 — 환경마다 다른 값

Supabase 키, API 키처럼 코드에 직접 적으면 안 되는 값은 Settings → Environment Variables에 등록합니다. 이때 값마다 Production / Preview / Development 중 어디에 적용할지를 고를 수 있어서, 실서비스 DB와 테스트 DB를 자연스럽게 분리할 수 있습니다.

# 터미널에서 등록할 때 (환경 이름을 뒤에 붙임)
vercel env add NEXT_PUBLIC_SUPABASE_URL production
vercel env add NEXT_PUBLIC_SUPABASE_URL preview

# Vercel에 등록된 값을 내 컴퓨터 .env.local로 내려받기
vercel env pull

같은 이름의 변수를 환경마다 다른 값으로 둘 수 있습니다 — 실서비스 DB와 테스트 DB 분리가 이렇게 됩니다

5-3. Serverless Functions — 서버 없이 API 만들기

브라우저에 노출되면 안 되는 API 키를 다루거나, 외부 API를 대신 호출해야 할 때 씁니다. Next.js라면 app/api/hello/route.ts처럼 파일을 만들면 그게 곧 /api/hello 주소가 되고, Next.js가 아닌 프로젝트라면 루트에 api/ 폴더를 만들어 같은 효과를 냅니다.

// app/api/hello/route.ts (Next.js App Router)
export async function GET() {
  return Response.json({ message: "안녕하세요" });
}

화면은 CDN에서 바로, /api/ 요청만 함수가 그때그때 처리합니다

5-4. Instant Rollback — 잘못 올렸을 때

Vercel은 모든 배포를 보관하므로, Deployments 목록에서 이전 배포의 ⋯ → Promote to Production(또는 Instant Rollback)을 누르면 즉시 그 시점으로 돌아갑니다. 다시 빌드하지 않아서 몇 초면 끝납니다.

5-5. 커스텀 도메인 · 이미지 최적화 · Analytics

  • 도메인 — Settings → Domains에서 직접 산 도메인을 연결하면 HTTPS는 자동입니다.
  • 이미지 최적화 — Next.js의 <Image>를 쓰면 Vercel이 기기에 맞는 크기·포맷으로 자동 변환해 줍니다.
  • Analytics / Speed Insights — 방문자 수와 페이지 속도를 대시보드에서 바로 봅니다. 무료 플랜에도 기본 수준은 포함됩니다.

6. Netlify와 무엇이 다른가

솔직히 말하면 80%는 같습니다. Git 연동 자동 배포, PR 미리보기, 무료 HTTPS, 롤백, 서버리스 함수 — 둘 다 있습니다. 차이는 나머지 20%에서 갈립니다.

항목VercelNetlify
가장 잘 맞는 프레임워크Next.js (만든 회사)특정 프레임워크에 치우치지 않음
드래그 앤 드롭 배포없음 (Git 또는 CLI)있음 — Git 몰라도 3분
폼 제출 받기직접 구현 필요Netlify Forms 속성 하나로
미리보기 화면에 댓글Vercel ToolbarNetlify Drawer (비슷)
AI 생태계v0, AI SDK 같은 회사—
무료 플랜 상업적 사용불가 (Hobby는 개인·비상업용)가능

정리 기준: Next.js나 v0 결과물 → Vercel. Git이 낯설거나 문의 폼이 필요 → Netlify. 저장소를 비공개로 두고 트래픽이 많음 → Cloudflare. 순수 문서·포트폴리오 → GitHub Pages.

위에서부터 차례로 물어보면 대체로 답이 나옵니다

7. 자주 겪는 문제

7-1. 빌드는 됐는데 새로고침하면 404 (React·Vite SPA)

Next.js가 아닌 Vite·CRA 프로젝트에서 /about을 새로고침하면 404가 납니다. 저장소 루트에 vercel.json을 만들고 모든 경로를 index.html로 돌려보내면 해결됩니다.

// vercel.json (저장소 루트)
{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}

7-2. "No Next.js version detected" / 빌드 실패

저장소 루트가 아니라 하위 폴더(frontend/, web/ 등)에 프로젝트가 있을 때 흔합니다. Settings → General → Root Directory에 그 폴더를 지정하면 됩니다.

7-3. Production은 되는데 Preview에서만 에러

환경 변수를 Production에만 등록해서 생기는 문제입니다. 등록할 때 Preview 체크박스도 함께 켜 주거나, vercel env add 이름 preview로 추가합니다.

7-4. 로컬에서는 되는데 배포하면 이미지·파일이 안 보임

Netlify와 같은 원인입니다. 빌드 서버(리눅스)는 파일명 대소문자를 구분합니다. Logo.png를 logo.png로 부르면 배포 후에만 깨집니다.

7-5. 무료(Hobby) 플랜 한도와 조건

개인 학습·포트폴리오에는 충분하지만 두 가지는 미리 알아 두세요. 첫째, Hobby 플랜은 비상업적 용도만 허용됩니다. 광고를 붙이거나 유료 서비스를 올리면 Pro 플랜으로 바꿔야 합니다. 둘째, 대역폭·서버리스 함수 실행 시간에 한도가 있고 이 숫자는 정책에 따라 바뀌므로 공식 요금 페이지에서 확인하세요.

8. 정리

  • Vercel = Next.js를 만든 회사의 배포 플랫폼, v0와 함께 한 회사 생태계
  • 핵심은 Production / Preview / Development 세 환경 — main은 실서비스, 나머지 브랜치는 미리보기
  • 시작은 대시보드 Import 또는 CLI(vercel, vercel --prod)
  • 막히는 지점은 대개 Root Directory, 환경 변수 스코프, SPA rewrites 세 가지
  • Netlify와 80%는 같으니, Next.js면 Vercel, 아니면 취향대로
