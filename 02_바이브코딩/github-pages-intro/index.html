GitHub Pages가 무엇인가

GitHub Pages는 GitHub 저장소에 올려 둔 파일을 그대로 웹사이트로 띄워 주는 무료 서비스입니다. 별도 회사에 가입할 필요도, 빌드 서버도, 설정 파일도 없습니다. 저장소 설정에서 스위치 하나를 켜면 사용자이름.github.io/저장소이름/ 주소가 생깁니다. 지금 보고 계신 이 사이트가 바로 그렇게 배포되어 있습니다. 이 과정에서 만나는 배포 서비스 네 가지(GitHub Pages · Netlify · Vercel · Cloudflare Pages) 중 가장 단순하고, 그래서 가장 먼저 배웁니다.

  • GitHub Pages가 정확히 무엇을 해 주고, 무엇을 안 해 주는지
  • 주소가 정해지는 규칙 두 가지
  • 가장 빠른 배포 — 설정 한 번으로 끝나는 방법
  • 빌드가 필요한 프로젝트를 올리는 방법 (GitHub Actions)
  • 다른 세 서비스로 "넘어가야 하는" 순간
  • 수업에서 실제로 자주 막히는 지점과 해결법

영상으로 먼저 보기: 사전학습 영상에 10분짜리 GitHub Pages 실습 영상이 있습니다. 이 교안은 그 영상에서 "왜 그렇게 되는지"를 채워 주는 개념 편입니다.

1. 한 줄로 말하면

GitHub Pages는 "저장소의 파일 = 웹사이트의 파일"로 만들어 주는 서비스입니다. 2008년부터 있었던 GitHub의 오래된 기능이고, 원래는 오픈소스 프로젝트의 소개 페이지를 올리라고 만든 것이었습니다. 그래서 철학이 단순합니다. 파일을 올리면 그 파일이 그 주소에서 열립니다. 그 이상은 하지 않습니다.

파일 하나가 주소 하나 — 빌드도 변환도 없습니다

1-1. 하는 것과 안 하는 것

하는 것안 하는 것
HTML·CSS·JS·이미지 파일을 그대로 서빙서버 쪽 코드 실행 (로그인 처리, DB 저장 등)
무료 HTTPS 주소 제공폼 제출 받기
push하면 1~2분 안에 반영PR마다 미리보기 주소 만들기
커스텀 도메인 연결private 저장소 배포 (무료 플랜)

오른쪽 칸이 필요해지는 순간이 다른 서비스로 넘어갈 때입니다. 뒤의 7장에서 다룹니다.

2. 주소가 정해지는 규칙 두 가지

GitHub Pages 주소는 저장소 이름이 결정합니다. 규칙은 딱 두 가지입니다.

종류저장소 이름생기는 주소
사용자 사이트사용자이름.github.io (정확히 이 이름)https://사용자이름.github.io/
프로젝트 사이트그 외 아무 이름 (예: my-app)https://사용자이름.github.io/my-app/

사용자 사이트는 계정당 하나만 만들 수 있고 보통 포트폴리오 대문으로 씁니다. 프로젝트 사이트는 저장소마다 하나씩 무제한입니다. 이 강의 노트도 frontierall_note_2608이라는 저장소의 프로젝트 사이트라서 주소에 저장소 이름이 붙어 있습니다.

저장소 이름이 곧 주소입니다 — 프로젝트 사이트는 뒤에 /저장소이름/ 이 붙습니다

여기서 생기는 함정: 프로젝트 사이트는 주소가 /my-app/ 아래에서 시작하기 때문에, HTML 안에서 /style.css처럼 슬래시로 시작하는 절대 경로를 쓰면 사용자이름.github.io/style.css를 찾다가 404가 납니다. 8장에서 자세히 다룹니다.

3. 실습 A — 설정 한 번으로 끝내기

순수 HTML 프로젝트라면 이게 전부입니다. 빌드도, 설정 파일도 없습니다.

  1. 저장소 루트(또는 docs/ 폴더)에 index.html이 있는지 확인합니다.
  2. GitHub 저장소 페이지에서 Settings → Pages로 들어갑니다.
  3. Source를 Deploy from a branch로 두고, 브랜치 main, 폴더 / (root)를 고른 뒤 Save.
  4. 1~2분 뒤 같은 화면 상단에 "Your site is live at …" 주소가 뜹니다.

이후로는 main에 push할 때마다 자동으로 다시 반영됩니다. 저장소 Actions 탭에서 "pages build and deployment"라는 작업이 돌아가는 것을 볼 수 있습니다.

3-1. .nojekyll — 빈 파일 하나가 하는 일

GitHub Pages는 기본적으로 Jekyll이라는 블로그 도구를 한 번 거칩니다. 순수 HTML이면 거의 영향이 없지만, Jekyll은 밑줄(_)로 시작하는 파일·폴더를 무시합니다. Vite·Next.js 결과물에는 _app, _next 같은 폴더가 흔해서, 이게 통째로 사라지면 사이트가 깨집니다. 저장소 루트에 .nojekyll이라는 내용 없는 빈 파일을 두면 Jekyll을 건너뛰고 파일을 그대로 올립니다. 이 강의 노트 저장소에도 그 파일이 있습니다.

# 터미널에서 빈 파일 만들기
touch .nojekyll
git add .nojekyll
git commit -m "Jekyll 처리 끄기"
git push

4. 실습 B — 빌드가 필요한 프로젝트 (GitHub Actions)

React(Vite) 같은 프로젝트는 소스 코드를 그대로 올리면 안 되고, npm run build로 만든 dist/ 폴더를 올려야 합니다. Netlify·Vercel은 이 빌드를 알아서 해 주지만, GitHub Pages에는 빌드 서버가 없습니다. 대신 GitHub Actions에게 빌드를 시키고 결과를 Pages에 넘기는 방식을 씁니다.

빌드가 필요한지에 따라 갈라지고, 결과 주소는 같습니다

  1. Settings → Pages → Source를 GitHub Actions로 바꿉니다.
  2. 저장소에 .github/workflows/deploy.yml 파일을 만듭니다.
  3. push하면 Actions가 빌드 → 업로드 → 배포를 순서대로 실행합니다.
# .github/workflows/deploy.yml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]

permissions:
  pages: write
  id-token: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist
      - uses: actions/deploy-pages@v4

Vite 프로젝트는 한 줄 더: 프로젝트 사이트는 주소가 /저장소이름/에서 시작하므로, vite.config.js에 base: '/저장소이름/'을 넣어야 빌드된 파일이 올바른 경로를 가리킵니다. 이걸 빼먹으면 빈 화면이 뜹니다.

// vite.config.js
export default {
  base: '/my-app/',
}

5. 알아 두면 좋은 것

5-1. 커스텀 도메인

Settings → Pages → Custom domain에 도메인을 입력하면 저장소 루트에 CNAME 파일이 생깁니다. 도메인 쪽 DNS에서 CNAME 레코드를 사용자이름.github.io로 가리키게 하고, 확인이 끝나면 Enforce HTTPS를 켭니다. 인증서는 자동입니다.

5-2. 반영이 느린 이유 — 캐시 10분

push 후 Actions가 초록불인데도 사이트가 안 바뀌어 보이는 경우가 있습니다. GitHub Pages가 파일을 약 10분간 캐시하기 때문입니다. 브라우저에서 하드 새로고침(Windows Ctrl+Shift+R, Mac Cmd+Shift+R)을 하거나 시크릿 창으로 열어 보면 대개 바로 보입니다. 이 강의 노트의 일부 페이지가 스크립트에 시간값을 붙여 불러오는 것도 이 캐시를 피하기 위한 처리입니다.

5-3. 404.html

루트에 404.html을 두면 없는 주소로 들어왔을 때 GitHub 기본 화면 대신 그 파일을 보여 줍니다. 홈으로 가는 링크 하나만 넣어 둬도 인상이 다릅니다.

6. 한계 — 무료 플랜 기준

항목GitHub Pages
private 저장소불가 (유료 플랜에서만 가능)
서버 코드·폼없음 — 정적 파일만
PR 미리보기 주소없음
상업적 사용제한적 — 온라인 상점 등 사업 운영 용도는 약관상 금지
사이트 크기 / 월 대역폭1GB / 100GB 권장 한도 (넘으면 안내가 옴)
빌드빌드 서버 없음 — Actions로 직접 구성

구체적인 숫자는 바뀔 수 있으니 공식 한도 문서를 참고하세요. 개인 학습·포트폴리오·문서 사이트에는 이 한도가 문제 되는 일이 거의 없습니다.

7. 언제 다른 서비스로 넘어가나

GitHub Pages는 출발점으로 가장 좋습니다. 계정도 이미 있고, 설정도 한 번이고, 개념도 "파일 = 주소"로 단순하니까요. 다만 아래 셋 중 하나가 필요해지는 순간, 그에 맞는 서비스로 옮기면 됩니다. 옮기는 데 드는 노력은 대개 10분 안쪽입니다.

필요해진 것넘어갈 곳이유
저장소를 비공개로 두고 싶다Cloudflare / Netlify / Vercel셋 다 private 저장소 무료 지원. 트래픽까지 많으면 Cloudflare
문의 폼을 받고 싶다, Git 없이 올리고 싶다NetlifyForms 속성 하나, 드래그 앤 드롭 배포
Next.js 프로젝트다Vercel만든 회사, 설정 없이 동작
PR 미리보기가 필요하다셋 중 아무 곳GitHub Pages만 이 기능이 없음

출발은 GitHub Pages, 필요가 생기면 그에 맞는 곳으로 — 옮기는 데 10분

정리 기준: 문서·포트폴리오·수업 결과물 공유 → GitHub Pages로 충분. 그 이상이 필요해지면 위 표에서 고릅니다. 이 강의 노트가 GitHub Pages와 Cloudflare 두 곳에 동시에 배포돼 있는 것도 "private으로 바꿔야 할 때를 대비한" 이유입니다.

8. 자주 겪는 문제

8-1. 주소로 들어가면 404

세 가지 중 하나입니다. 순서대로 확인하세요.

  • 선택한 브랜치·폴더에 index.html이 없다 (Index.html, home.html은 안 됩니다)
  • Settings → Pages에서 Source가 None으로 되어 있다 (저장 안 됨)
  • 방금 켰다 — 첫 배포는 최대 몇 분 걸립니다. Actions 탭에서 초록불을 확인하세요

8-2. 화면은 뜨는데 CSS·이미지가 안 나온다 (가장 흔함)

프로젝트 사이트에서 절대 경로를 쓴 경우입니다. /style.css는 사용자이름.github.io/style.css를 가리키는데, 실제 파일은 사용자이름.github.io/my-app/style.css에 있으니 못 찾습니다. 슬래시 없이 상대 경로로 바꾸면 해결됩니다.

<!-- ✕ 절대 경로 — 프로젝트 사이트에서 깨짐 -->
<link rel="stylesheet" href="/style.css">
<img src="/images/logo.png">

<!-- ○ 상대 경로 — 어디서든 동작 -->
<link rel="stylesheet" href="style.css">
<img src="images/logo.png">

로컬에서 file://로 열 때는 둘 다 되는 것처럼 보이거나 둘 다 안 되기 때문에 눈치채기 어렵습니다. 처음부터 상대 경로 습관을 들이는 게 가장 안전합니다.

슬래시 하나 차이 — 프로젝트 사이트에서는 /my-app/ 이 빠져 버립니다

8-3. 로컬에서는 되는데 배포하면 이미지가 안 보인다

GitHub Pages 서버(리눅스)는 파일명 대소문자를 구분합니다. Logo.png를 logo.png로 부르면 배포 후에만 깨집니다. 파일명은 전부 소문자로 통일하세요.

8-4. push했는데 안 바뀐다

5-2절의 캐시 문제입니다. 하드 새로고침 또는 시크릿 창으로 확인하세요. 그래도 안 바뀌면 Actions 탭에서 배포가 실제로 성공했는지 봅니다.

8-5. _로 시작하는 폴더가 통째로 사라졌다

3-1절의 Jekyll 문제입니다. 루트에 .nojekyll 빈 파일을 추가하세요.

8-6. 저장소를 private으로 바꿨더니 사이트가 꺼졌다

무료 플랜의 정상 동작입니다. 다시 public으로 돌리거나, Cloudflare 등 private 저장소를 지원하는 서비스로 옮깁니다.

9. 정리

  • GitHub Pages = 저장소 파일이 곧 웹사이트, 설정 한 번이면 끝
  • 주소는 저장소 이름이 정한다 — 사용자이름.github.io는 대문, 나머지는 /저장소이름/
  • 빌드가 필요하면 GitHub Actions가 대신하고, Vite는 base 설정 필수
  • 가장 흔한 사고는 절대 경로, 대소문자, 캐시 10분, .nojekyll 네 가지
  • private 저장소·폼·미리보기가 필요해지는 순간 다른 셋으로 — 옮기는 데 10분
