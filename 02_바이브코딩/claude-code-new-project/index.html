Claude Code에서 새 프로젝트 만들기

Claude Code로 아이디어를 코드로 옮길 때, 코드 작성만큼 중요한 것이 저장소·배포·데이터베이스를 연결하는 절차입니다. 이 교안은 실제 프로젝트(ClassShelf) 작업 중 진행한 세 가지 연동 과정을 그대로 정리한 실습 자료입니다.

  • GitHub 저장소 생성과 push
  • Vercel CLI로 프로젝트 연결과 배포 준비
  • Supabase Personal Access Token 발급과 DB 연동

1. GitHub 저장소 생성 · push

Claude Code는 터미널 위에서 동작하므로, GitHub CLI(gh)가 로그인되어 있으면 저장소 생성부터 push까지 대화로 진행할 수 있습니다.

1-1. 로그인 상태 확인

gh auth status

계정이 여러 개 등록되어 있다면 Active account: true로 표시된 계정이 실제로 사용됩니다.

1-2. 커밋과 push

git add .
git commit -m "커밋 메시지"
git push origin main

실전 트러블슈팅: push 시 HTTP 401 오류가 나면 로컬 git 자격 증명이 gh 로그인 토큰과 연결되어 있지 않은 경우가 많습니다. 아래 명령으로 git이 gh의 인증을 쓰도록 다시 연결하면 해결됩니다.

gh auth setup-git
git push origin main

1-3. 기본 브랜치까지 병합

혼자 작업하는 저장소라면, 커밋한 브랜치가 기본 브랜치(main)와 fast-forward 관계인지 확인하고, 가능하면 바로 main까지 병합·push하는 것이 편합니다. 기본 브랜치가 이미 분기(diverge)되어 있다면 병합 커밋을 만들지 리베이스할지 먼저 판단해야 합니다.

2. Vercel CLI로 프로젝트 연결

새 저장소를 Vercel에 연결할 때는 vercel link를 쓰는데, 몇 가지 함정이 있습니다.

2-1. 링크 상태 먼저 점검

이미 .vercel/project.json이 있어도 실제 계정에 그 프로젝트가 없을 수 있습니다. 아래 명령으로 먼저 확인합니다.

vercel project ls

여기 없는 프로젝트 이름이 로컬에 링크되어 있다면, 끊어진(stale) 링크입니다. 삭제하고 다시 연결합니다.

rm -rf .vercel
vercel link --yes

실전 트러블슈팅: 폴더 이름에 대문자나 --가 섞여 있으면 자동 생성되는 프로젝트 이름이 Vercel 명명 규칙(소문자, --- 연속 금지)에 걸려 실패할 수 있습니다. 이럴 때는 프로젝트를 먼저 명시적으로 만들고 이름을 지정해 연결합니다.

vercel project add my-project-name
vercel link --yes --project my-project-name

2-2. GitHub 저장소 연결

CLI로 만든 프로젝트는 GitHub 연동이 자동으로 붙지 않을 수 있습니다. 아래 명령으로 명시적으로 연결하면, 이후 main push마다 자동 배포가 시작됩니다.

vercel git connect

2-3. 프레임워크 프리셋 확인

CLI로 프로젝트를 새로 만들면 프레임워크가 Other로 잡히는 경우가 있습니다. vercel.json에 명시해서 빌드 명령을 정확히 지정합니다.

{
  "framework": "nextjs"
}

3. Supabase Personal Access Token 발급 + DB 연동

Claude Code가 Supabase CLI로 프로젝트를 만들고 마이그레이션을 적용하려면, 먼저 계정 인증이 필요합니다. 브라우저 자동 로그인이 안 되는 환경(터미널 전용 세션 등)에서는 Personal Access Token(PAT)을 발급해서 전달하는 방식을 씁니다.

3-1. Access Tokens 페이지 접속

사용하려는 Supabase 계정으로 로그인한 뒤, 아래 주소로 이동합니다.

https://supabase.com/dashboard/account/tokens

3-2. 새 토큰 생성

Generate new token 버튼을 클릭하면 이름과 만료 기간을 입력하는 창이 뜹니다.

토큰 이름은 용도를 알아볼 수 있게 지정합니다. (예: classshelf-cli)

3-3. 토큰 복사

생성 직후 한 번만 전체 값이 표시됩니다. 이 화면을 벗어나면 다시 볼 수 없으므로 바로 복사해서 안전한 곳에 둡니다.

보안 주의: PAT는 계정 전체를 제어할 수 있는 자격 증명입니다. 대화창이나 캡처 이미지에 노출했다면, 작업이 끝난 뒤 Access Tokens 페이지에서 반드시 폐기(revoke)합니다.

3-4. CLI 인증

supabase login --token "sbp_..." --name my-account

3-5. 프로젝트 생성과 연결

supabase orgs list
supabase projects create my-project \
  --org-id <조직 ID> \
  --region ap-northeast-2 \
  --db-password "<강한 임의 비밀번호>" \
  --yes

supabase link --project-ref <생성된 project ref>

실전 트러블슈팅: 무료 플랜은 조직당 활성 프로젝트 수(보통 2개)가 제한되어 있습니다. 한도에 걸리면 기존 프로젝트를 정리하거나, 다른 계정/조직으로 로그인해 진행할 수 있습니다.

3-6. 마이그레이션과 시드 데이터 적용

supabase db push --linked --yes
supabase db query --linked --file supabase/seed.sql --yes

3-7. API 키 확인과 환경 변수 등록

supabase projects api-keys --project-ref <project ref> --output-format json

여기서 얻은 URL, anon key, service_role key를 로컬 .env.local과 Vercel 환경 변수에 각각 등록합니다.

vercel env add NEXT_PUBLIC_SUPABASE_URL production
vercel env add NEXT_PUBLIC_SUPABASE_ANON_KEY production
vercel env add SUPABASE_SERVICE_ROLE_KEY production

4. 전체 흐름 요약

단계도구핵심 명령
저장소 생성·pushGitHub CLIgh auth setup-git, git push
배포 연결Vercel CLIvercel link, vercel git connect
DB 연동Supabase CLIsupabase login --token, supabase link, supabase db push

세 도구 모두 CLI 인증이 선행되어야 Claude Code가 명령을 대신 실행할 수 있습니다. 인증 정보(토큰, 서비스 키)는 항상 .env.local 등 Git에 커밋되지 않는 파일에만 두고, 대화나 캡처에 노출된 값은 작업 후 폐기하는 습관을 들입니다.
