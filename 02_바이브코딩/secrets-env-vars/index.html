Hands-on Secrets · 실습 교안

GitHub Secrets ·
Vercel 환경변수 등록하기

API 키나 Webhook 주소 같은 비밀값을 코드에 직접 적지 않고, GitHub Actions와 Vercel이 안전하게 읽을 수 있는 곳에 등록하는 법을 웹 UI와 CLI 두 가지 방법으로 직접 실습합니다.

대상: GitHub Actions·Vercel 배포를 시작한 분예상 시간: 25–35분필요한 것: GitHub 저장소 + Vercel 프로젝트

오늘의 학습 목표

  • 비밀값을 코드나 커밋에 직접 넣으면 안 되는 이유를 설명한다.
  • GitHub 웹 UI에서 저장소 Secret을 등록한다.
  • gh secret set으로 터미널에서 Secret을 등록한다.
  • 워크플로우 .yml에서 secrets.이름으로 값을 불러온다.
  • Vercel 대시보드에서 환경변수를 Production/Preview/Development로 나눠 등록한다.
  • vercel env CLI로 환경변수를 추가하고 로컬로 가져온다.
  • GitHub Secrets와 Vercel 환경변수 중 어디에 등록해야 하는지 구분한다.

지난 실습에서 만든 뉴스 다이제스트 프로젝트를 예시로 씁니다. Secret/환경변수 이름은 DISCORD_WEBHOOK_URL, ANTHROPIC_API_KEY 두 개를 그대로 사용하지만, 실제 값은 여러분이 각자 발급받은 것으로 채워야 합니다. 이 문서의 값 자체는 전부 예시입니다.

1. 왜 코드에 직접 쓰면 안 되나

Webhook 주소나 API 키가 새어나가면, 그 즉시 다른 사람이 내 이름으로 메시지를 보내거나 내 API 사용량으로 결제될 수 있습니다.

코드에 직접 쓰면

const key = "sk-ant-..."처럼 값을 파일에 그대로 적으면, 저장소를 clone하거나 열람할 수 있는 모두가 그 값을 볼 수 있습니다. GitHub이 private이어도 협업자·CI 로그·포크 과정에서 노출될 위험이 남습니다.

한 번 commit되면

나중에 파일을 지우고 다시 commit해도, Git 기록(history)에는 그 값이 그대로 남습니다. 값이 새어나갔다면 파일을 지우는 게 아니라 그 키/Webhook 자체를 폐기하고 새로 발급해야 합니다.

이미 commit해버렸다면일단 그 값부터 발급처(Discord 서버 설정, Anthropic 콘솔 등)에서 폐기하고 새로 발급하세요. Git 기록에서 지우는 작업은 그다음입니다 — 폐기가 먼저입니다.

그래서 코드에는 "이 이름의 값을 어딘가에서 가져와 쓴다"는 참조만 남기고, 실제 값은 GitHub과 Vercel이 따로 안전하게 보관하는 곳에 등록합니다. GitHub Actions가 쓸 값은 GitHub Secrets에, 배포된 앱이 쓸 값은 Vercel 환경변수에 둡니다.

2. GitHub Secrets · 웹에서 등록

가장 직관적인 방법입니다. 값이 화면에 다시 노출되지 않아 실수로 공유될 위험도 적습니다.

1

저장소 Settings로 이동

GitHub에서 저장소를 열고 Settings → Secrets and variables → Actions로 들어갑니다.

2

New repository secret 클릭

Repository secrets 탭에서 New repository secret 버튼을 누릅니다.

3

이름과 값 입력

Name에는 워크플로우에서 참조할 이름을 대문자와 언더스코어로 적습니다 (예: DISCORD_WEBHOOK_URL). Secret란에는 실제 값을 붙여넣습니다.

이름 규칙영문 대문자·숫자·언더스코어만 가능하고 숫자로 시작할 수 없습니다. GITHUB_로 시작하는 이름은 예약되어 있어 쓸 수 없습니다.
4

Add secret으로 저장

저장 후에는 값을 다시 볼 수 없습니다. 목록에는 이름과 마지막 수정일만 표시됩니다. 값을 바꾸려면 같은 이름으로 새로 등록(덮어쓰기)하면 됩니다.

3. GitHub Secrets · CLI로 등록

터미널을 벗어나지 않고 등록하고 싶을 때, 또는 여러 저장소에 반복 등록할 때 편합니다. GitHub CLI 실습에서 인증까지 마쳤다면 바로 쓸 수 있습니다.

1

대화형으로 등록

값을 입력하라는 프롬프트가 뜹니다. 터미널에 값이 그대로 보이므로 화면 공유 중에는 피하세요.

Terminal
gh secret set DISCORD_WEBHOOK_URL --repo frontierall/mynews-2608
2

값을 파일이나 변수로 전달 (화면에 안 남기고 싶을 때)

Terminal · 파일에서 읽기
gh secret set ANTHROPIC_API_KEY --repo frontierall/mynews-2608 < key.txt
key.txt는 임시 파일입니다등록이 끝나면 바로 삭제하고, .gitignore에도 이런 임시 파일 패턴을 추가해두세요.
3

등록된 이름 확인

여기서도 값 자체는 볼 수 없습니다 — 이름과 갱신 시각만 확인됩니다.

Terminal
gh secret list --repo frontierall/mynews-2608
4

더 이상 안 쓰는 값 삭제

Terminal
gh secret delete OLD_SECRET_NAME --repo frontierall/mynews-2608

4. 워크플로우에서 Secret 사용하기

등록만으로는 아무 일도 일어나지 않습니다. 워크플로우 .yml 파일에서 secrets.이름 문법으로 불러와야 실제로 쓰입니다.

.github/workflows/discord-digest.yml
jobs:
  digest:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: npm run send-discord-digest
        env:
          DISCORD_WEBHOOK_URL: ${{ secrets.DISCORD_WEBHOOK_URL }}
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}

${{ secrets.DISCORD_WEBHOOK_URL }}이 실행 시점에 실제 값으로 치환되어, 그 아래 스크립트에서는 일반 환경변수(process.env.DISCORD_WEBHOOK_URL)처럼 읽으면 됩니다.

로그에도 안 남습니다GitHub Actions는 Secret로 등록된 값이 로그 출력에 그대로 찍히면 자동으로 ***로 가려줍니다. 다만 값을 가공해서(예: base64 인코딩) 출력하면 가려지지 않으니 애초에 값을 출력하는 코드를 넣지 않는 게 안전합니다.

5. Vercel 환경변수 · 웹 대시보드에서 등록

GitHub Secrets가 Actions 실행 중에만 쓰이는 값이라면, Vercel 환경변수는 배포된 앱 자체가 빌드·실행 중에 읽는 값입니다.

1

프로젝트 Settings로 이동

Vercel 대시보드에서 프로젝트를 연 뒤 Settings → Environment Variables로 들어갑니다.

2

Key/Value 입력

이름(Key)과 값(Value)을 입력합니다. GitHub Secrets와 이름을 맞춰두면(예: 여기도 ANTHROPIC_API_KEY) 헷갈리지 않습니다.

3

적용할 환경(Environment) 선택

Vercel은 값마다 어느 배포 환경에 적용할지 고를 수 있습니다.

환경언제 쓰이나
Production연결된 기본 브랜치(보통 main)가 배포된, 실제 서비스 중인 배포
PreviewPR·다른 브랜치를 push할 때마다 자동으로 생기는 미리보기 배포
Developmentvercel dev로 로컬에서 돌릴 때
운영 키와 테스트 키를 나누고 싶다면같은 이름의 변수를 Production에는 운영용 값으로, Preview에는 테스트용 값으로 각각 다르게 등록할 수 있습니다.
4

저장 후 반드시 재배포

이미 배포되어 있던 버전에는 자동으로 반영되지 않습니다. 환경변수를 새로 등록하거나 바꾼 뒤에는 Deployments 탭에서 최신 배포를 Redeploy하거나, 새 commit을 push해서 다시 빌드해야 값이 적용됩니다.

6. Vercel 환경변수 · CLI로 등록하고 로컬로 가져오기

터미널에서 등록하거나, 팀원의 값을 그대로 내 로컬 개발 환경에 맞춰 받아올 때 씁니다.

1

환경변수 추가

환경(production/preview/development)을 지정해서 추가합니다. 값을 입력하라는 프롬프트가 뜹니다.

Terminal
vercel env add ANTHROPIC_API_KEY production
2

등록된 목록 확인

Terminal
vercel env ls
3

로컬 개발용으로 가져오기

Vercel에 등록된 Development 환경변수를 로컬 파일로 내려받습니다. 이러면 팀원마다 값을 직접 주고받지 않아도 됩니다.

Terminal
vercel env pull .env.local
.env.local은 커밋 금지Next.js는 .env.local을 .gitignore에 기본으로 넣어줍니다만, 다른 프레임워크라면 직접 확인하세요.
4

더 이상 안 쓰는 값 삭제

Terminal
vercel env rm OLD_VAR production

7. 둘 중 어디에 등록하나

같은 값이라도 "누가 읽는가"에 따라 등록할 곳이 다릅니다. 헷갈리면 이 표부터 봅니다.

GitHub SecretsVercel 환경변수
누가 읽나GitHub Actions 워크플로우 실행 중Vercel에 배포된 앱(빌드·런타임)
예시2시간마다 뉴스를 수집하는 collect-news.yml, 매일 Discord로 다이제스트를 보내는 discord-digest.yml화면에서 API를 호출하거나, 서버 컴포넌트가 DB에 접속할 때
등록 방법웹 UI 또는 gh secret set웹 UI 또는 vercel env add
적용 시점다음 워크플로우 실행부터 즉시재배포해야 반영
같은 값을 양쪽에 다 등록해야 할 때이번 뉴스 다이제스트 프로젝트의 ANTHROPIC_API_KEY가 그런 경우입니다. GitHub Actions가 요약을 만들 때도 쓰고, 만약 화면에서도 실시간으로 API를 호출한다면 Vercel에도 같은 값을 등록해야 합니다. 등록 위치는 코드가 실행되는 곳을 기준으로 정합니다.

8. 자주 만나는 문제

"등록했는데 안 된다"의 대부분은 아래 넷 중 하나입니다.

증상가능한 원인확인·해결
워크플로우에서 값이 빈 문자열로 옴Secret 이름 오타, 또는 env:에 매핑을 안 함gh secret list로 이름을 정확히 대조하고, ${{ secrets.이름 }} 철자를 다시 확인합니다.
Vercel 배포에서 undefined등록 후 재배포를 안 함Deployments 탭에서 최신 배포를 Redeploy하거나 새 commit을 push합니다.
브라우저 콘솔에서 값이 안 보임(의도한 동작)서버 전용 변수는 클라이언트에 노출되지 않음Next.js 기준, 브라우저에서도 필요한 값만 NEXT_PUBLIC_ 접두사를 붙여 별도로 등록합니다. 비밀값에는 이 접두사를 쓰지 않습니다.
Pull Request의 Preview 배포에서만 값이 없음Production에만 등록하고 Preview 체크박스를 빼먹음Vercel 환경변수 등록 시 적용할 환경(Production/Preview/Development)을 다시 확인합니다.

9. 실습 과제

실제 값을 발급받아 등록까지 마쳐야 완료입니다.

실습 체크리스트

  1. Discord Webhook URL 발급 (서버 → 채널 설정 → 연동 → 웹후크)
  2. Anthropic API 키 발급 (console.anthropic.com → API Keys)
  3. GitHub 웹 UI로 DISCORD_WEBHOOK_URL 등록
  4. gh secret set으로 ANTHROPIC_API_KEY 등록
  5. gh secret list로 둘 다 등록됐는지 확인
  6. 워크플로우를 수동 실행(workflow_dispatch 또는 Actions 탭)해서 실제로 값이 전달되는지 확인
  7. 필요하다면 Vercel에도 같은 값을 Production으로 등록
  8. Vercel에서 Redeploy 후 반영 확인

형성 평가

Q1. Secret 값을 코드에 커밋했다가 지웠다면 안전한가?
아닙니다. Git 기록에는 여전히 남아 있으므로, 그 값을 발급처에서 폐기하고 새로 발급해야 합니다.
Q2. GitHub에 등록한 Secret 값을 나중에 웹에서 다시 확인할 수 있나?
아니요. 이름과 갱신 시각만 확인할 수 있고, 값 자체는 등록 후 다시 조회할 수 없습니다.
Q3. Vercel 환경변수를 새로 등록했는데 배포된 사이트에 반영이 안 된다면?
이미 배포된 버전에는 자동 반영되지 않습니다. Redeploy하거나 새 commit을 push해야 합니다.
Q4. 워크플로우에서 ${{ secrets.API_KEY }}는 무엇을 하나?
GitHub Secrets에 등록된 API_KEY 값을 실행 시점에 불러와 그 자리에 치환합니다.
Q5. GitHub Actions와 배포된 Vercel 앱이 둘 다 같은 API 키를 쓴다면?
GitHub Secrets와 Vercel 환경변수 양쪽에 같은 값을 각각 등록해야 합니다. 한쪽 등록은 다른 쪽에 자동으로 반영되지 않습니다.

강사용 진행 메모

시연 전

실습용 더미 Webhook과 임시 API 키를 미리 준비합니다. 화면 공유 중에는 gh secret set 대화형 입력보다 < key.txt 방식을 시연해 값이 안 보이게 합니다.

시연 중

"등록 후 값을 다시 볼 수 없다"를 강조하고, 등록 직후 gh secret list/Vercel 목록에서 값이 아니라 이름만 보인다는 걸 직접 확인시킵니다.

시연 후

실습에 쓴 더미 키는 수업이 끝나면 폐기하도록 안내합니다. 공용 계정을 썼다면 gh secret delete로 정리합니다.
