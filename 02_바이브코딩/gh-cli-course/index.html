Clone과 퍼블리시까지

터미널에서 gh를 설치하고 GitHub 계정을 연결한 뒤, 비공개 저장소를 clone하고 로컬 프로젝트를 원격 GitHub에 퍼블리시하는 전 과정을 직접 실습합니다.

1. Git과 GitHub CLI는 무엇이 다른가?

두 도구는 협력하지만 담당 범위가 다릅니다.

git — 버전 관리

로컬 변경 이력, 브랜치, 커밋, 원격 저장소와의 push/pull을 담당합니다.

git status · git commit · git push

gh — GitHub 기능

GitHub 로그인, 저장소 조회·생성·clone, 이슈와 Pull Request 등을 터미널에서 다룹니다.

gh auth login · gh repo list · gh repo clone

CLI 설치기기 인증저장소 조회CloneCommit·Push연결 검증

2. Git 핵심 명령어 이해하기

저장소를 만든 뒤 실제 작업은 이 7개 명령어를 반복하며 진행합니다. 이후 실습에서 그대로 쓰이니 먼저 역할부터 정확히 익혀 둡니다.

명령어역할예시
git status현재 작업 폴더의 변경 상태를 확인합니다.git status --short
git add변경한 파일을 다음 commit에 포함되도록 준비(stage)합니다.git add README.md
git commitstaged된 변경사항을 하나의 기록(스냅샷)으로 저장합니다.git commit -m "메시지"
git push로컬 commit을 원격 저장소(GitHub)에 업로드합니다.git push
git branch브랜치를 만들거나 목록을 확인합니다.git branch feature/login
git fetch원격 저장소의 변경 내역을 가져오되, 아직 내 작업에 합치지는 않습니다.git fetch origin
git merge다른 브랜치의 변경 내역을 현재 브랜치에 합칩니다.git merge feature/login
status·add·commit·push는 이미 실습합니다이 4개 명령어는 7. 로컬 프로젝트를 GitHub에 퍼블리시에서 실제로 손으로 실행해 봅니다. 여기서는 나머지 branch·fetch·merge를 집중적으로 다룹니다.
1

브랜치 만들고 이동하기

main 브랜치를 바로 건드리는 대신, 작업마다 독립된 브랜치를 만들면 실수해도 되돌리기 쉽습니다.

Terminal
git branch feature/login
git switch feature/login

두 명령을 합친 git switch -c feature/login(또는 예전 방식인 git checkout -b feature/login)도 자주 씁니다.

2

원격 변경사항 가져오기 — fetch

다른 사람이 push한 내용은 자동으로 반영되지 않습니다. fetch로 먼저 받아와서 확인합니다.

Terminal
git fetch origin
git log origin/main --oneline -5
fetch와 pull의 차이fetch는 원격 내역만 내려받고 내 브랜치는 그대로 둡니다. pull은 fetch 다음에 merge까지 자동으로 실행하는 단축 명령입니다.
3

브랜치 병합하기 — merge

작업이 끝난 브랜치를 main에 합칩니다. 합치기 전에 main도 최신 상태인지 확인하는 습관을 들입니다.

Terminal
git switch main
git fetch origin
git merge feature/login

변경 지점이 겹치지 않으면 자동으로 합쳐지는 fast-forward merge가 일어나고, 같은 부분을 서로 다르게 고쳤다면 아래처럼 충돌(conflict)이 발생합니다.

브랜치 생성작업 · CommitPushFetchMerge브랜치 정리
4

merge 충돌 해결 실습

충돌은 실수가 아니라 여러 사람이 같은 코드를 함께 고칠 때 자연스럽게 생기는 상황입니다. 침착하게 아래 순서로 해결합니다.

Terminal · merge 시도
git merge feature/login
# Auto-merging README.md
# CONFLICT (content): Merge conflict in README.md
# Automatic merge failed; fix conflicts and then commit the result.
충돌이 표시된 파일 내용
<<<<<<< HEAD
현재 브랜치(main)의 내용
=======
합치려는 브랜치(feature/login)의 내용
>>>>>>> feature/login

파일을 열어 원하는 내용만 남기고 <<<<<<<·=======·>>>>>>> 표시를 모두 지운 뒤 마무리합니다.

Terminal · 해결 후
git status
git add README.md
git commit
안전망해결이 막막하면 git merge --abort로 merge 시도 자체를 취소하고 병합 전 상태로 되돌릴 수 있습니다.

4. 웹 기기 인증으로 GitHub 연결

비밀번호나 토큰을 터미널에 직접 붙여 넣지 않는 브라우저 인증 흐름입니다.

1

로그인 명령 실행

Terminal
gh auth login -h github.com -p https -w
  • -h github.com: 인증할 호스트
  • -p https: Git 작업에 HTTPS 사용
  • -w: 브라우저 인증 사용
2

기기 코드 입력

브라우저에서 github.com/login/device를 열고 현재 터미널에 표시된 코드를 입력합니다.

3

계정과 권한을 확인한 뒤 승인

로그인 계정과 요청 권한이 수업 목적에 맞는지 확인합니다. 비공개 저장소는 해당 계정에 접근 권한이 있어야 합니다.

4

추가 본인 확인이 나오면 완료

GitHub 보호 기능에 따라 이메일 확인이 요청될 수 있습니다. 계정 설정과 최근 인증 상태에 따라 생략될 수도 있습니다.

5

인증 상태 확인

Terminal
gh auth status

Logged in to github.com account codeclass-demo와 비슷한 메시지가 보이면 성공입니다.

보안 원칙--show-token 결과, OAuth 코드, 이메일 인증 코드는 화면 공유·녹화·과제 제출물에 포함하지 마세요.

5. 원격 저장소 찾기

인증 후에는 현재 계정이 접근 가능한 비공개 저장소도 조회할 수 있습니다.

1

저장소 목록 확인

Terminal
gh repo list codeclass-demo --limit 100
2

이름으로 필터링

Terminal · macOS/Linux
gh repo list codeclass-demo --limit 100 \
  --json name,nameWithOwner,url,visibility \
  --jq '.[] | select((.name | ascii_downcase) | contains("lesson"))'

간단히 확인할 때는 gh repo list codeclass-demo | grep -i lesson도 사용할 수 있습니다.

왜 웹 검색만으로 부족할까?검색 엔진과 로그아웃 상태의 GitHub 웹은 비공개 저장소를 보여주지 않습니다. 인증된 gh는 현재 계정 권한 안에서 조회합니다.

6. 비공개 저장소 Clone

저장소를 내려받을 상위 폴더로 이동한 뒤 clone합니다.

1

대상 폴더 확인

Terminal
pwd
ls -la

현재 폴더가 비어 있지 않으면 저장소 이름의 하위 폴더에 clone하는 편이 안전합니다.

2

OWNER/REPO 형식으로 Clone

Terminal
gh repo clone codeclass-demo/lesson-script-2608

로컬 폴더명을 따로 지정할 수도 있습니다.

Terminal
gh repo clone codeclass-demo/lesson-script-2608 my-local-folder
3

연결 상태 검증

Terminal
cd lesson-script-2608
git status --short --branch
git remote -v

origin이 https://github.com/codeclass-demo/lesson-script-2608.git을 가리키면 정상입니다.

7. 로컬 프로젝트를 GitHub에 퍼블리시

여기서 퍼블리시는 로컬 파일을 Git으로 기록한 뒤 새 GitHub 원격 저장소를 만들고 최초 push하는 과정을 뜻합니다.

업로드 전 필수 점검.env, API 키, 비밀번호, 개인정보, 대용량 생성 파일이 포함되지 않았는지 확인하세요. 비밀값은 한 번 commit하면 나중에 지워도 Git 기록에 남을 수 있습니다.
1

프로젝트 폴더와 파일 범위 확인

Terminal · 프로젝트 폴더에서
pwd
ls -la
git status

not a git repository가 나오면 아직 Git 저장소가 아니라는 뜻이므로 다음 단계에서 초기화합니다. 이미 저장소라면 기존 origin부터 확인하세요.

2

Git 저장소 초기화와 .gitignore 준비

Terminal
git init
git status --short

프로젝트 종류에 맞는 .gitignore를 만든 뒤 최소한 다음 항목을 검토합니다.

.gitignore 예시
.env
.env.*
!.env.example
node_modules/
.DS_Store
3

첫 Commit 만들기

Terminal
git add .
git status --short
git diff --cached --stat
git commit -m "Initial commit"
git branch -M main

git status와 staged diff를 확인한 뒤 commit합니다. 수업에서는 학생이 “어떤 파일이 올라가는가?”를 말로 확인하게 하세요.

4

새 GitHub 저장소 생성과 최초 Push

비공개 저장소로 퍼블리시
gh repo create codeclass-demo/lesson-script-2608 \
  --private \
  --source=. \
  --remote=origin \
  --push
  • --private: 비공개 저장소로 생성
  • --source=.: 현재 로컬 프로젝트 사용
  • --remote=origin: 원격 이름을 origin으로 등록
  • --push: 로컬 commit을 즉시 업로드
공개 저장소가 필요하다면소스와 문서에서 비밀값·개인정보·라이선스 문제를 다시 검토한 뒤 --private 대신 --public을 사용합니다.
5

퍼블리시 결과 검증

Terminal
git status --short --branch
git remote -v
gh repo view codeclass-demo/lesson-script-2608 --web

작업 트리가 깨끗하고 현재 브랜치가 origin/main을 추적하며, 브라우저에서 파일이 보이면 최초 퍼블리시가 완료된 것입니다.

6

이후 변경사항을 Commit하고 Push

clone했거나 이미 퍼블리시한 저장소에서는 아래 반복 주기를 사용합니다.

파일 수정StatusDiff 확인StageCommitPush
Terminal · 예시
git status --short
git diff
git add README.md
git diff --cached
git commit -m "docs: update lesson notes"
git push
좋은 습관git add .를 습관적으로 쓰기보다 필요한 파일을 지정하고, commit 직전에 git diff --cached로 최종 내용을 검토합니다.

8. 선택 실습: 원격 저장소 이름 변경

실제 URL을 바꾸므로 소유자 또는 관리자 권한이 필요합니다.

1

원격 저장소 이름 변경

Terminal
gh repo rename lesson-script-renamed \
  --repo codeclass-demo/lesson-script-2608 \
  --yes
2

로컬 폴더와 origin URL 정리

저장소 상위 폴더
mv lesson-script-2608 lesson-script-renamed
git -C lesson-script-renamed remote set-url origin \
  https://github.com/codeclass-demo/lesson-script-renamed.git
git -C lesson-script-renamed remote -v
주의공동 작업자, 문서, CI/CD, 배포 서비스에 이전 URL이 하드코딩되어 있다면 함께 수정합니다.

9. 자주 만나는 오류와 해결법

오류 메시지를 지우지 말고 첫 줄부터 읽는 습관을 들입니다.

증상가능한 원인확인·해결
gh: command not found미설치 또는 PATH 미반영gh --version 확인. Windows는 터미널 창을 다시 엽니다.
The token ... is invalid저장된 인증 만료gh auth login -h github.com -p https -w로 다시 인증합니다.
저장소가 목록에 없음다른 계정 활성화 또는 권한 없음gh auth status 확인 후 필요하면 gh auth switch를 사용합니다.
Repository not foundOWNER/REPO 오타 또는 권한 없음gh repo view codeclass-demo/lesson-script-2608로 확인합니다.
현재 폴더에 clone 실패대상 폴더가 비어 있지 않음상위 폴더에서 저장소명 하위 폴더로 clone합니다.
nothing to commit변경 파일이 없거나 아직 저장되지 않음git status로 파일 상태와 현재 폴더를 확인합니다.
remote origin already exists이미 원격 저장소가 연결됨git remote -v로 기존 URL을 확인하고 새 저장소를 만들지, URL을 바꿀지 결정합니다.
Push가 거절됨원격에 로컬에 없는 commit이 있음무조건 force push하지 말고 git pull --rebase가 적절한지 공동 작업 상황부터 확인합니다.
이름 변경 후 push 실패origin이 이전 URL을 가리킴git remote -v 확인 후 URL을 갱신합니다.
CONFLICT (content)두 브랜치가 같은 파일의 같은 부분을 다르게 수정git status로 충돌 파일을 확인하고 직접 편집한 뒤 git add · git commit. 되돌리려면 git merge --abort.
You are in 'detached HEAD' state브랜치가 아니라 특정 commit을 직접 checkout함계속 작업하려면 git switch -c 새브랜치로 브랜치를 만들고, 아니면 git switch main으로 돌아갑니다.

형성 평가

Q1. git과 gh의 차이는?
git은 분산 버전 관리 도구이고 gh는 GitHub 서비스 기능을 다루는 CLI입니다.
Q2. 비공개 저장소가 안 보일 때 첫 점검은?
gh auth status로 올바른 계정과 접근 권한을 확인합니다.
Q3. 기기 인증 코드를 공유하면 안 되는 이유는?
짧은 시간 동안 GitHub 권한 승인을 연결하는 자격 증명 역할을 하기 때문입니다.
Q4. gh repo create --source=. --push는 무엇을 하는가?
현재 로컬 프로젝트를 바탕으로 GitHub 저장소를 만들고 원격을 연결한 뒤, 기존 로컬 commit을 GitHub로 push합니다.
Q5. 첫 commit 전 반드시 확인할 것은?
.gitignore, staged 파일 목록, 비밀값·개인정보·대용량 파일 포함 여부를 확인합니다.

강사용 진행 메모

시연 전

테스트 계정을 준비하고 화면 공유 알림·이메일 미리보기를 끕니다. 개인 저장소 대신 수업용 저장소를 사용합니다.

시연 중

인증 코드를 촬영하지 않도록 안내하고, 각 권한의 의미를 읽은 뒤 승인하는 습관을 강조합니다.

시연 후

gh auth status와 git remote -v를 학생이 말로 해석하게 합니다. 공용 PC에서는 로그아웃합니다.

공용 PC 수업 종료 시
gh auth logout -h github.com -u codeclass-demo

  • GitHub CLI 설치 안내
  • gh auth login · gh auth status
  • gh repo list · gh repo clone · gh repo create · gh repo rename
  • git branch · git fetch · git merge
