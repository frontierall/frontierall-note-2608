Netlify가 무엇인가

바이브 코딩으로 만든 결과물은 결국 남에게 보여 줘야 의미가 생깁니다. 내 노트북에서만 열리는 index.html은 아직 "웹사이트"가 아니니까요. Netlify(넷리파이)는 그 마지막 한 걸음, 즉 "만든 걸 인터넷 주소가 있는 사이트로 올리는 일"을 가장 쉽게 해 주는 서비스입니다.

  • Netlify가 정확히 무엇을 대신해 주는 서비스인지
  • 가장 빠른 배포 두 가지 — 드래그 앤 드롭, GitHub 연동
  • 알아 두면 좋은 기능(미리보기 배포, 롤백, 폼, 함수)
  • GitHub Pages · Vercel · Cloudflare와 무엇이 다른지
  • 수업에서 실제로 자주 막히는 지점과 해결법

1. 한 줄로 말하면

Netlify는 내가 만든 웹사이트 파일을 대신 보관하고, 전 세계 어디서든 빠르게 열리도록 인터넷에 띄워 주는 서비스입니다. 여기에 "GitHub에 코드를 올리면 알아서 다시 배포까지 해 주는" 자동화가 붙어 있습니다.

2014년에 시작해 Jamstack이라는 말을 만들어 낸 회사이기도 합니다. 지금 우리가 당연하게 쓰는 "Git에 push하면 자동 배포", "PR마다 미리보기 주소" 같은 흐름을 대중화한 원조격 서비스라고 보면 됩니다.

1-1. 예전에는 이렇게 했습니다

Netlify 같은 서비스가 없던 시절에 사이트를 하나 띄우려면 이런 일을 직접 해야 했습니다.

  1. 서버(호스팅)를 돈 주고 빌린다
  2. FTP 프로그램으로 파일을 하나씩 서버에 올린다
  3. 도메인을 사고 서버 주소와 연결한다
  4. HTTPS(자물쇠) 인증서를 발급받아 서버에 설치한다
  5. 파일을 고칠 때마다 다시 FTP로 덮어쓴다

Netlify는 이 다섯 단계를 폴더 하나 끌어다 놓기 또는 GitHub 저장소 연결하기로 줄여 놓은 서비스입니다. 도메인 연결과 HTTPS도 자동입니다.

다섯 단계가 두 단계로 줄어듭니다

용어 정리 — 배포(deploy): 내 컴퓨터에 있는 파일을 인터넷에서 누구나 볼 수 있는 곳으로 옮겨 두는 일을 말합니다. "배포한다 = 사이트를 인터넷에 올린다"로 이해하면 충분합니다.

2. Netlify가 대신 해 주는 세 가지

push 한 번이면 이 흐름 전체가 자동으로 돕니다

역할하는 일
빌드(Build)React·Next.js처럼 변환이 필요한 코드를 브라우저가 읽을 수 있는 파일로 만들어 줍니다. 순수 HTML이면 이 단계는 건너뜁니다.
배포(Deploy)완성된 파일을 실제 서비스 주소에 반영합니다. 새 버전이 올라가도 이전 버전은 그대로 보관됩니다.
호스팅(Hosting)전 세계에 흩어진 서버(CDN)에 파일을 복사해 두어, 어느 나라에서 접속해도 가까운 곳에서 빠르게 열리게 합니다.

이 세 가지가 한 세트로 묶여 있고, 무료 플랜에서도 HTTPS 인증서가 자동으로 발급·갱신됩니다. 주소창에 자물쇠가 뜨게 하려고 따로 할 일이 없습니다.

파일을 올리는 방법은 크게 두 가지이고, 어느 쪽을 택하든 결과물은 똑같습니다.

두 방법 모두 결과는 같은 주소 하나입니다

3. 실습 A — 3분 만에 사이트 띄우기(드래그 앤 드롭)

Git을 아직 몰라도 됩니다. 가장 먼저 해 볼 실습입니다.

  1. 바탕화면에 폴더를 하나 만들고 그 안에 index.html 파일을 넣습니다.
  2. app.netlify.com/drop에 접속합니다.
  3. 화면 가운데 점선 영역에 폴더째로 끌어다 놓습니다.
  4. 몇 초 뒤 랜덤이름.netlify.app 주소가 생기고, 그 주소로 바로 접속됩니다.
<!-- index.html — 이 정도만 있어도 배포됩니다 -->
<!DOCTYPE html>
<html lang="ko">
<head><meta charset="UTF-8"><title>내 첫 사이트</title></head>
<body>
  <h1>안녕하세요 👋</h1>
  <p>Netlify로 올린 첫 페이지입니다.</p>
</body>
</html>

주소에 붙은 랜덤 이름(festive-tesla-1a2b3c 같은 것)은 Site configuration → Site details → Change site name에서 원하는 이름으로 바꿀 수 있습니다.

Cloudflare Workers와 다른 점: 같은 파트의 Cloudflare Workers 교안에서는 프로젝트 이름을 나중에 바꾸기 어려웠지만, Netlify는 사이트 이름(주소)을 나중에 자유롭게 변경할 수 있습니다. 처음 이름을 크게 고민하지 않아도 됩니다.

주의: 파일이 아니라 폴더를 끌어다 놓아야 합니다. 그리고 폴더 안 최상위에 index.html이 있어야 첫 화면이 뜹니다. 이름이 Index.html이나 home.html이면 "Page not found"가 나옵니다.

4. 실습 B — GitHub 연동 자동 배포

드래그 앤 드롭은 빠르지만, 수정할 때마다 다시 끌어다 놓아야 합니다. 실제 프로젝트에서는 GitHub 저장소를 연결해서 push할 때마다 자동으로 배포되게 합니다.

  1. Netlify 대시보드에서 Add new site → Import an existing project를 선택합니다.
  2. Deploy with GitHub를 누르고 GitHub 앱 권한을 승인합니다. (저장소 전체 또는 선택한 저장소만 고를 수 있습니다.)
  3. 배포할 저장소를 선택합니다.
  4. 빌드 설정을 확인하고 Deploy를 누릅니다.

4-1. 빌드 설정에서 딱 두 칸만 보면 됩니다

항목순수 HTML 사이트React(Vite)Next.js
Build command(비워 둠)npm run buildnpm run build
Publish directory. (또는 public)dist자동 감지

Publish directory는 "완성된 파일이 들어 있는 폴더"를 뜻합니다. 배포는 성공했는데 사이트가 빈 화면이거나 404라면, 십중팔구 이 칸이 잘못 지정된 것입니다.

4-2. 설정을 파일로 남겨 두기 (netlify.toml)

대시보드에서 클릭으로 설정해도 되지만, 저장소 루트에 netlify.toml을 두면 설정이 코드와 함께 관리되어 훨씬 안전합니다.

# netlify.toml (저장소 루트)
[build]
  command = "npm run build"
  publish = "dist"

순수 HTML 저장소라면 이 파일 없이도 잘 동작합니다.

5. 알아 두면 좋은 기능

5-1. Deploy Preview — PR마다 생기는 미리보기 주소

Pull Request를 올리면 Netlify가 그 PR 내용만 반영된 별도 주소를 자동으로 만들어 주고, PR 화면에 링크를 댓글로 남깁니다. "말로 설명하지 말고 링크를 보여 주는" 협업이 가능해집니다. 해커톤 팀 작업에서 특히 유용합니다.

5-2. 즉시 롤백 — 사고 났을 때 30초 복구

Netlify는 배포할 때마다 이전 버전을 지우지 않고 전부 보관합니다. 잘못 올렸다면 Deploys 목록에서 예전 배포를 고르고 Publish deploy만 누르면 그 시점으로 즉시 되돌아갑니다. 코드를 되돌리거나 다시 빌드할 필요가 없습니다.

5-3. 커스텀 도메인 + 무료 HTTPS

직접 산 도메인(mysite.com)을 Domain management에서 연결할 수 있고, 인증서는 Let's Encrypt로 자동 발급·자동 갱신됩니다.

5-4. Netlify Forms — 서버 없이 문의 폼 받기

HTML 폼 태그에 속성 하나만 추가하면, 제출된 내용이 Netlify 대시보드에 쌓입니다. 백엔드도 DB도 필요 없습니다.

<form name="contact" method="POST" data-netlify="true">
  <input type="text" name="name" placeholder="이름">
  <input type="email" name="email" placeholder="이메일">
  <textarea name="message"></textarea>
  <button type="submit">보내기</button>
</form>

5-5. Netlify Functions — 서버 없이 뒷단 코드 돌리기

netlify/functions/ 폴더에 JS 파일을 두면 그것이 그대로 API 주소(/.netlify/functions/파일명)가 됩니다. API 키처럼 브라우저에 노출되면 안 되는 값을 다뤄야 할 때 사용합니다.

6. 비슷한 서비스와 비교

서비스성격이럴 때 고릅니다
GitHub Pages가장 단순. 저장소 파일을 그대로 서빙순수 HTML 문서·포트폴리오. 단, 무료 플랜은 private 저장소 불가
Netlify드래그 앤 드롭·폼·함수까지 골고루Git을 아직 안 배웠거나, 폼·미리보기가 필요할 때
VercelNext.js를 만든 회사Next.js 프로젝트, v0로 만든 결과물
Cloudflare Workers/PagesCDN 성능과 관대한 무료 한도트래픽이 많고 대역폭 비용이 걱정될 때

기능이 상당 부분 겹치기 때문에, 정답은 없고 상황과 취향의 문제입니다. 이 수업에서는 이 네 가지를 모두 한 번씩 경험해 보고 본인에게 맞는 것을 고르면 됩니다.

네 서비스의 대략적인 위치 — 오른쪽으로 갈수록 기능이 많고 배울 것도 늘어납니다

정리 기준: Git이 아직 낯설다 → Netlify 드래그 앤 드롭. 문서만 올린다 → GitHub Pages. Next.js다 → Vercel. 저장소를 비공개로 두고 싶다 → GitHub Pages만 빼면 어디든 가능, 트래픽까지 많으면 Cloudflare.

7. 자주 겪는 문제

7-1. 새로고침하면 404가 뜹니다 (React·Vue 등 SPA)

첫 화면은 잘 뜨는데 /about에서 새로고침하면 "Page not found"가 나옵니다. 주소에 해당하는 실제 파일이 없기 때문입니다. 배포 폴더에 _redirects 파일을 만들고 아래 한 줄을 넣으면 해결됩니다.

# _redirects (publish 폴더 안, 확장자 없음)
/*    /index.html   200

주소는 그대로 두고 index.html을 돌려주면, 화면 전환은 앱이 알아서 처리합니다

7-2. 로컬에서는 되는데 배포하면 이미지가 안 나옵니다

윈도우·맥은 파일 이름의 대소문자를 구분하지 않지만, Netlify의 빌드 서버(리눅스)는 구분합니다. Logo.png 파일을 logo.png로 불러오면 로컬에서만 성공하고 배포 후에는 깨집니다. 파일명은 전부 소문자로 통일하는 습관이 안전합니다.

7-3. 빌드가 실패합니다

Deploys 화면에서 실패한 배포를 클릭하면 전체 로그를 볼 수 있습니다. 흔한 원인은 세 가지입니다.

  • Publish directory를 잘못 지정 (dist인데 build로 적음)
  • package-lock.json을 커밋하지 않아 의존성 설치 실패
  • 로컬에만 있던 .env 값이 서버에는 없음 → Site configuration → Environment variables에 직접 등록해야 합니다

7-4. 무료 플랜 한도

개인 학습·포트폴리오 수준에서는 무료 플랜으로 충분하고, 상업용 사이트도 무료 플랜에서 배포할 수 있습니다(Vercel Hobby와 다른 점). 다만 2025년 9월부터 신규 계정은 크레딧 기반 요금제로 바뀌어, Free 플랜은 월 300 크레딧이 상한이고 대역폭·빌드 시간이 모두 여기서 차감됩니다. 유료 Pro는 2026년 4월부터 시트당 과금 없이 월 $20 정액·팀원 무제한으로 바뀌어, 해커톤 팀이 함께 쓰기에 부담이 줄었습니다. 이 숫자는 정책에 따라 바뀌므로 실제 값은 공식 요금 페이지에서 확인하세요. 한도가 걱정될 만큼 트래픽이 늘었다면 Cloudflare 쪽이 대안이 됩니다.

8. 정리

  • Netlify = 빌드 + 배포 + 호스팅을 한 번에 해 주는 서비스, HTTPS는 자동
  • 가장 빠른 시작은 폴더 드래그 앤 드롭 — Git 없이 3분
  • 실제 프로젝트는 GitHub 연동으로, push할 때마다 자동 배포
  • 막히는 지점은 대개 Publish directory와 파일명 대소문자 두 가지
  • 사이트 이름(주소)은 나중에 바꿀 수 있으니 부담 없이 시작하세요

용어가 헷갈릴 때는 용어사전의 Netlify · Vercel · Cloudflare Pages · GitHub Pages 항목을 함께 보면 서로의 관계가 정리됩니다.
