Node.js 설치 후 PowerShell에서 npm이 실행되지 않음

출처 · 프론티어올 러닝 노트 (실습 환경 세팅)

증상

Node.js를 정상적으로 설치했는데도 PowerShell에서 npm -v 같은 명령을 실행하면 아래 오류가 나면서 명령이 아예 시작되지 않는다.

한글 Windows

npm : 이 시스템에서 스크립트를 실행할 수 없으므로 C:\Program Files\nodejs\npm.ps1
파일을 로드할 수 없습니다. 자세한 내용은 about_Execution_Policies
(https://go.microsoft.com/fwlink/?LinkID=135170)를 참조하십시오.
위치 줄:1 문자:1
+ npm -v
+ ~~~
    + CategoryInfo          : 보안 오류: (:) [], PSSecurityException
    + FullyQualifiedErrorId : UnauthorizedAccess

영문 Windows

npm : File C:\Program Files\nodejs\npm.ps1 cannot be loaded because running scripts
is disabled on this system. For more information, see about_Execution_Policies at
https://go.microsoft.com/fwlink/?LinkID=135170.
    + CategoryInfo          : SecurityError: (:) [], PSSecurityException
    + FullyQualifiedErrorId : UnauthorizedAccess

판별 키워드 — 오류 메시지에 PSSecurityException과 UnauthorizedAccess가 함께 보이면 100% 이 문제다. 반대로 EACCES·EPERM이 보이면 파일 권한 문제이지 실행 정책 문제가 아니다.

원인

PowerShell의 ExecutionPolicy(스크립트 실행 정책)에 막힌 것이다. Windows 클라이언트의 기본값은 Restricted로, .ps1 스크립트 파일 실행을 전면 차단한다. 인터넷에서 받은 악성 스크립트를 더블클릭 한 번으로 실행해버리는 사고를 막기 위한 안전장치다.

문제는 Windows용 npm이 npm.ps1이라는 PowerShell 스크립트로 동작한다는 점이다. 그래서 Node.js 설치 자체는 성공했어도 PowerShell에서 npm을 부르는 순간 정책에 걸린다. npm의 버그가 아니라 PowerShell이 npm 실행을 거부한 것이다.

어떤 명령까지 막히나

npm 하나만의 문제가 아니라, PowerShell 스크립트로 감싸진 CLI 전체가 같은 오류를 낸다. 즉 개발 도구 CLI가 통째로 마비된다.

  • npm, npx, yarn, pnpm, pnpx
  • 전역 설치한 도구 — tsc, ng(Angular), vue, next, vite, nodemon, eslint 등
  • 버전 관리 도구 — nvm, fnm
  • 직접 만든 .ps1 스크립트, 프로젝트의 setup.ps1

헷갈리기 쉬운 지점

아래 특징들 때문에 원인을 엉뚱한 곳에서 찾다가 시간을 많이 쓴다. 수업 중 가장 자주 나오는 오해다.

  • node -v는 정상 작동한다. node.exe는 스크립트가 아니라 실행 파일이라 정책과 무관하다. 그래서 "Node는 깔렸는데 npm만 안 되네?" 하며 Node.js를 계속 재설치하게 된다.
  • CMD(명령 프롬프트)에서는 멀쩡하다. CMD는 npm.cmd를 실행하기 때문이다. VS Code 터미널이 PowerShell이면 거기서만 오류가 나고, CMD로 바꾸면 되는 이상한 상황이 생긴다.
  • 관리자 권한으로 실행해도 해결되지 않는다. 권한 문제가 아니라 정책 문제다.
  • 오류 메시지 맨 앞에 npm :이 붙어서 npm 자체 버그처럼 보인다.

3초 자가진단

확인해석
node -v 정상 + npm -v 오류ExecutionPolicy 의심
CMD에서는 되고 PowerShell에서만 오류ExecutionPolicy 확정
오류에 UnauthorizedAccess 포함ExecutionPolicy 확정
오류에 EACCES / EPERM 포함다른 문제 (파일 권한)

정책 종류

값의미
Restricted스크립트 전부 차단 (Windows 클라이언트 기본값)
AllSigned서명된 스크립트만 허용
RemoteSigned로컬에서 만든 스크립트는 그대로 실행, 인터넷에서 받은 것은 서명 필요
Unrestricted경고만 띄우고 모두 실행
Bypass아무것도 막지 않음

RemoteSigned를 권장한다. npm처럼 로컬에 설치된 스크립트는 문제없이 돌아가면서, 인터넷에서 다운로드한 파일은 여전히 걸러준다. 보안을 크게 포기하지 않는 선택이다.

해결

# 1. 현재 상태 확인
Get-ExecutionPolicy -List

# 2. 현재 사용자에게만 적용 (관리자 권한 불필요, 권장)
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# 3. 확인 메시지가 나오면 Y 입력

# 4. 적용 확인
npm -v

-Scope CurrentUser를 붙이는 것이 핵심이다. 시스템 전체(LocalMachine)가 아니라 내 계정에만 적용되므로 관리자 권한 없이 실행되고, 같은 PC의 다른 사용자에게도 영향이 없다.

변경 후 PowerShell 창을 새로 열어 npm -v로 확인한다.

정책을 바꿀 수 없는 경우 (회사 · 교육장 PC)

그룹 정책(GPO)으로 강제된 환경에서는 Set-ExecutionPolicy가 먹지 않는다. Get-ExecutionPolicy -List에서 MachinePolicy·UserPolicy 항목에 값이 잡혀 있으면 GPO로 강제된 상태다. 이때는 아래 우회책을 쓴다.

  • CMD 사용 — CMD는 npm.cmd를 실행하므로 정책 영향을 받지 않는다. VS Code에서는 터미널 기본 프로필을 Command Prompt로 바꾸면 된다.
  • 한 번만 임시로 우회 — powershell -ExecutionPolicy Bypass로 새 셸을 띄우면 그 창에서만 정책이 풀린다. 설정을 영구히 바꾸지 않는다.
  • IT 부서에 요청 — 실습 전에 RemoteSigned 적용을 미리 요청해 두는 것이 가장 깔끔하다.

주의 — 편하다는 이유로 Bypass나 Unrestricted를 시스템 전체에 적용하지 않는다. 인터넷에서 받은 .ps1이 확인 없이 실행되는 상태가 되어, 이 정책이 원래 막으려던 위험이 그대로 열린다.

재발 방지

  • 실습 환경 세팅 안내에 Node.js 설치 → Set-ExecutionPolicy -Scope CurrentUser RemoteSigned → npm -v 확인을 한 세트로 포함한다. Node.js 설치만 안내하면 PowerShell 사용자에게서 반드시 이 문제가 재현된다.
  • PC를 새로 세팅하거나 계정을 새로 만들면 정책이 기본값(Restricted)으로 돌아오므로 다시 설정해야 한다.
  • 수강생 화면 공유 시 node -v와 npm -v를 함께 실행하게 하면, 이 문제인지 Node.js 설치 실패인지 즉시 구분된다.
