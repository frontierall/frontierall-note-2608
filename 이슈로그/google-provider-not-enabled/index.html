Supabase · Google OAuth

Google 로그인 시 "Unsupported provider: provider is not enabled"

출처 · ClassShelf-codex-2608

증상

로그인 화면에서 "Google로 로그인" 버튼을 눌렀을 때 아래 오류가 발생했다.

{"code":400,"error_code":"validation_failed","msg":"Unsupported provider: provider is not enabled"}

원인

앱 코드(signInWithGoogle 서버 액션, /auth/callback 라우트, 로그인 페이지 버튼)는 이미 배포되어 있었지만, Supabase Auth 프로젝트 설정에서 Google Provider가 활성화되지 않은 상태였다. Supabase는 각 OAuth Provider(Google, GitHub 등)를 프로젝트별로 별도 활성화해야 하며, 비활성 상태에서 signInWithOAuth({ provider: "google" })를 호출하면 이 오류를 반환한다.

Google Provider를 쓰려면 Google Cloud Console에서 발급한 OAuth 클라이언트(Client ID·Secret)가 필요하다 — 이건 Supabase나 Vercel API로 대신 만들 수 없고, 사용자가 Google Cloud Console에서 직접 발급해야 한다.

해결 순서

  1. Google Cloud Console에서 OAuth 클라이언트 생성
    • https://console.cloud.google.com/apis/credentials
    • OAuth 동의 화면 구성 (User Type: 외부)
    • 사용자 인증 정보 만들기 → OAuth 클라이언트 ID → 애플리케이션 유형: 웹 애플리케이션
    • 승인된 리디렉션 URI에 Supabase의 고정 콜백 URL 등록: 
      https://{project-ref}.supabase.co/auth/v1/callback
  2. Supabase Auth 설정 확인 (필드명 확인 후 값 채우기)

    먼저 현재 상태를 확인한다.

    curl -s "https://api.supabase.com/v1/projects/{project-ref}/config/auth" \
  -H "Authorization: Bearer {supabase-access-token}" \
  | jq '{external_google_enabled, external_google_client_id, external_google_secret}'
  3. Management API로 Provider 활성화 
    curl -X PATCH "https://api.supabase.com/v1/projects/{project-ref}/config/auth" \
  -H "Authorization: Bearer {supabase-access-token}" \
  -H "Content-Type: application/json" \
  -d '{
    "external_google_enabled": true,
    "external_google_client_id": "{google-oauth-client-id}",
    "external_google_secret": "{google-oauth-client-secret}"
  }'

    응답의 external_google_secret은 평문이 아니라 암호화된 해시로 표시된다 — 정상이다.

  4. 동작 검증 (브라우저 없이 서버 사이드에서 먼저 확인 가능) 
    curl -sD - -o /dev/null \
  "https://{project-ref}.supabase.co/auth/v1/authorize?provider=google&redirect_to={site-url}/auth/callback" \
  -H "apikey: {anon-key}"

    302 응답과 location: https://accounts.google.com/o/oauth2/v2/auth?... 헤더가 나오면 Provider가 정상 활성화된 것이다. 이 단계에서 redirect_uri 파라미터가 1번에서 Google Cloud Console에 등록한 값과 정확히 일치하는지 반드시 대조한다 — 다르면 Google이 redirect_uri_mismatch 오류로 막는다.

  5. 브라우저에서 실제 로그인 확인

    Production 로그인 페이지에서 버튼을 눌러 Google 계정 선택 → 동의 → 앱으로 정상 리다이렉트되는지 확인.

함께 확인해야 하는 것: 계정 자동 연결

기존에 이메일/비밀번호로 가입되어 있던 이메일과 같은 이메일로 Google 로그인을 하면, Supabase가 두 로그인 수단(email, google)을 자동으로 같은 사용자(같은 auth.users.id)에 연결한다. 즉 이미 admin 권한이 부여된 계정이라면 Google로 로그인해도 별도 승격 작업 없이 그대로 관리자 권한이 유지된다.

select provider, user_id from auth.identities where user_id = '{user-id}';
-- email, google 두 provider가 같은 user_id로 묶여 있으면 정상 연결된 것

재발 방지

  • 새 OAuth Provider(GitHub, Kakao 등)를 추가할 때도 동일하게 "앱 코드 배포"와 "Supabase Provider 활성화"가 별개 작업이라는 점을 기억한다. 코드만 배포하고 Provider 활성화를 빠뜨리면 이 오류가 재현된다.
  • Provider 활성화에 필요한 Client ID/Secret은 절대 저장소나 문서에 평문으로 기록하지 않는다. 값 전달은 사용자와의 대화로만 하고, 커밋 전 git diff --cached로 시크릿이 섞이지 않았는지 확인한다.

이 교안과 함께 보면 좋습니다: Claude Code로 구글 로그인 구현하기 — Google Cloud Console에서 OAuth 클라이언트를 발급하는 화면 흐름을 다룹니다.
